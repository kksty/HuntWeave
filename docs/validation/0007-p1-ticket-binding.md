# P1-① 票据目标绑定与策略版本：多目标归因验证

日期：2026-10-09（Asia/Shanghai）。对应 Issue [#9](https://github.com/kksty/HuntWeave/issues/9)，依据 P1 规格第 4 节①档、第 3.10 节与第 5 节，以及 `PROJECT.md` §4.2、§7.3。本轮把执行票据从「写死授权清单首项与字面量策略版本」改为「按该动作实际要执行的目标绑定，并在授权快照范围内逐项校验」。真实执行仍未开放，验收只用固定假执行与一次性数据库。

## 问题与判定

`runs/orchestration.py` 构造票据时写死 `target_ip=ip_address(scope.targets[0])`、`target_port=scope.ports[0]`、`policy_version=1`：

- 一个多目标多端口的 Run 会把**每一次**调用记在第一个目标与第一个端口上，票据只记录「有调用」，不记录证据属于哪个 `IP + transport + port`；假执行下这只是记录不准，真实执行下它是证据归属错误与逐目标范围校验缺失。
- `policy_version` 是字面量却参与 Run 级 fencing 比较（`scope_policy_mismatch`），策略版本事实上无法表达变化。

## 实现

| 改动点 | 行为 |
| --- | --- |
| 票据目标绑定 | `resolve_target(decision, scope, ordinal)` 是唯一的绑定点。计划自行命名目标时按 `targets`/`ports` 逐项校验后使用；未命名时取该 Run 的**下一个**授权端点（按调用序号在授权端点集内轮转），不再固定取首项 |
| 越界拒绝 | 计划命名了授权快照之外（或只命名一半、无法解析）的目标一律 `scope_denied`：不建票据、不预留预算、不写 outbox，Run 停在 `waiting` 并记录 `scope_denied` 事件（含被拒的计划目标与授权集合规模），任务置 `blocked` |
| 重派绑定 | 「确认未执行」后的重派是同一个原始动作，沿用原票据的目标绑定，不会改到第二个端点 |
| 策略版本 | `EXECUTION_POLICY_VERSION` 是唯一版本源，在授权时写入 `ScopeSnapshot.policy_version`；票据取 `scope.policy_version`。已存快照不被当前构建覆盖，活跃 Run 不会在票据之下悄悄换策略 |
| 策略版本校验 | 快照的 `policy_version` 必须为 ≥1 的整数；缺省值来自版本常量 |

## 验证

| 行为 | 结果 |
| --- | --- |
| 命名授权内的目标 → 精确绑定该目标 | 单元检查：计划命名第二目标第二端口时票据绑定为该值，而不是首项 |
| 命名越界目标 → 拒绝而非改派 | 单元检查参数化覆盖：IP 不在授权集、端口不在授权集、只命名其一、地址不可解析、端口不是整数，一律 `scope_denied` |
| 未命名目标 → 逐次覆盖授权端点 | 单元检查：`(192.0.2.7,80) → (192.0.2.7,443) → (192.0.2.8,80) → (192.0.2.8,443)`，四次互不相同且越界回绕 |
| 策略版本来自授权快照 | 单元检查：新快照记录版本常量；已存快照的版本被保留；`0` 被拒绝 |
| 多目标多端口 Run 的不同绑定 | 一次性栈集成检查：两个目标 × 两个首层端口，前三次动作分别绑定三个互不相同的端点，全部落在授权集合内，三次票据的 `policy_version` 等于该快照的 `policy_version` |
| 越界计划在占用资源前被拒 | 一次性栈集成检查：桩 Adapter 给出授权外目标后，`tool_calls` 为空、预算预留为 0、Run 为 `waiting` 且 `reason_code=scope_denied`、`scope_denied` 事件恰好一条 |
| 既有路径不回退 | 假执行路径的既有检查全部通过（见下方计数） |
| 结果计数 | 本地非集成检查 66 项通过、4 项跳过（含本轮新增 9 项），ruff 与严格 mypy 通过；一次性栈内后端检查 107 项全部通过（`python -m pytest tests`），其中与本项相关的 13 项（新增单元检查 9 项 + `test_orchestration_integration.py` 4 项）定向重跑全部通过 |

## 未达成与限制

- **真实执行仍关闭**（`real_execution_ready=false`）：本轮只改动票据构造与校验，未接真实执行端；真实动作的逐目标范围校验与出口规则仍由 #18 交付。
- **生产链路上目前不会自然产生越界计划**：确定性 Adapter 不自行命名目标（它的上下文不带目标集合），目标由 `runs` 按调用序号在授权端点集内轮转选取。因此「计划命名越界目标被拒绝」这条由单元检查与桩 Adapter 覆盖；#17 接入真实动作后由真实规划命名目标并走同一校验，届时才是端到端路径。
- **界面仍不显示逐调用目标**：票据已按目标绑定，但调用视图/控制台尚未展示。这属于 [#19](https://github.com/kksty/HuntWeave/issues/19) 的「只读六项」范围。
- **新原因码只显示原文**：控制台直接渲染 `reason_code`，因此 `scope_denied` 目前显示为代码本身而非中文说明；这与 P1 规格第 4 节②档「前端原因码文案映射与后端实际发出的原因码不一致」同属 #19 的验收项，本轮不重复处理。
- 每 IP 串行、调度公平与并发上限仍属 #17/#21，本轮未触及。
- 本轮不改变界面与接口形状，因此未重复运行浏览器流程与故障探针；能力诚实性（#10）与 `version_conflict` 静默重发（#11）仍开放。
