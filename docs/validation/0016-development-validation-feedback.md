# 开发验证反馈：Key 入口、会话隔离与等待上限

日期：2026-10-10（Asia/Shanghai）。跟踪任务：[GitHub #23](https://github.com/kksty/HuntWeave/issues/23)。开发决定见 [ADR-0018](../adr/0018-backend-first-and-layered-validation.md)，命令见 [README](../../README.md#验证)。

## 环境与改动

Windows 工作区 `D:\自动化渗透平台`，前端使用仓库现有依赖与本机已安装的 Chromium；浏览器入口为 `http://127.0.0.1:8000`。只对本机平台运行定点检查，没有创建目标执行或连接外部目标。

`frontend/playwright.config.ts` 的单项上限由 90 秒改为 30 秒，导航为 10 秒、交互与断言为 5 秒、整轮为 180 秒，零重试；默认首个失败停止。`test:e2e:full` 覆盖后续用例，仍受整轮上限约束。

`frontend/tests/fixtures.ts` 通过登录 API 为每项业务检查创建独立会话，主动打开工作台并等待项目列表；退出登录不会影响另一项检查。入口检查使用匿名页面。旧的全局登录/共享 Cookie 准备已删除，本轮临时共享会话已撤销并移除其本地状态文件。检查只修改测试准备与测试等待参数，不调整目标执行的超时或租约。

## 未覆盖与限制

运行中的 app 与数据库版本不匹配且反复重启，这一环境不能支持有效的端到端结论。服务与当前源码同步并恢复健康后，须重新执行会话隔离和页面初始化的定点检查；本记录不把类型检查或快速失败记为浏览器通过。

本轮未重复运行完整浏览器套件、后端全集、数据库迁移与故障探针；后端取消登录限速的历史验证不由本轮重新宣称。后端先行的后续切片使用其对应 API、数据库与执行验证，前端集中接入及阶段最终交付再进行浏览器验收。

## 收尾复验（2026-10-10）

按 `ask-matt` 路由执行诊断和标准/需求两轴复审。一次性项目为 `huntweave-p0-checks`，入口 `http://127.0.0.1:18000`，使用当前源码构建的 app/runner/checks；应用 schema 约束与数据库迁移均为 `0007_drop_login_throttle`，`login_buckets` 已不存在。

### 根因与修复

- 旧运行服务版本不匹配解释了最初的连接失败；同版本健康服务上，独立会话与主动导航解决了空白页/缺少 `execution-readiness` 的准备问题。
- 项目响应头先到达，Vue 的 `load()` 尚在继续，表单仍禁用并可能被折叠。fixture 改为等待表单启用；新建项目 helper 只按当前可见状态展开，删除反复点击的中间方案。
- 暂停/恢复/取消/结束的控制接口存在真实 500：内部 `RunView.model_dump()` 带计算字段 `demonstration`，API 再校验时拒绝该字段，而控制状态已提交。内部序列化排除该派生字段，API 再计算公开值，沿用 snapshot/reconciliation 的既有约定。
- 补充 HTTP 回归 `test_control_response_preserves_derived_run_fields`：修复前因 `extra_forbidden` 失败，修复后返回 200 并保留状态、版本、执行 profile 与公开派生字段。该问题直接用后端接口验证。
- 业务控制可能收到真实版本冲突。用例只在明确的 `409/version_conflict` 后点击页面的确认按钮；其他错误立即失败。冲突专用用例冻结草稿显示，再由真实 API 启动 Run，确定地产生版本变化，保留首次不重发与人工确认后的重发检查。
- 当前 Run 的状态断言限定详情区域，避免侧栏历史记录造成假通过；核对错误告警限定预期文案，允许“停止未确认”告警同时存在。

测试假动作使用受支持参数设为 1000 毫秒，保留在途控制窗口，生产默认与目标工具的时限不变。页面交互/显示断言仍为 5 秒；完整假 Run 的异步终态通过只读 API 观察最多 15 秒，再核对界面，整项仍为 30 秒、整轮 180 秒。该区分避免用 30/60 秒的元素断言掩盖后台执行或错误响应。

曾直接在活跃 app 同库运行全部后端检查，出现 1 项手动队列测试被 agentd 抢任务（259 通过、1 失败、2 跳过）。按验证层职责分开后通过：需要自行领取任务的检查独占数据库，启动检查再使用活跃 app；README 已同步命令。浏览器阶段重新初始化一次性数据库，避免人工构造的租约和未决状态干扰真实用户流程。

Windows Docker BuildKit 首次从中文路径构建报非 ASCII 会话头错误，临时使用 `subst X:` 映射同一工作区完成构建，不复制 secrets 或历史证据；开发依赖下载属于镜像准备时间，不计入浏览器运行耗时。

本次只使用固定假动作、文档保留 IP 与本机 API。没有连接外部目标，真实执行开放门槛未改变；未重跑与本次接口修复无关的完整靶场隔离/出口/恢复故障探针。

收尾时日常 `huntweave` 服务使用同一已验证控制镜像升级至迁移 `0007_drop_login_throttle`，app/postgres/runner 均 healthy，登录计数表不存在；日常数据卷保留。一次性验证项目的容器、网络与测试卷已回收，临时盘符映射移除。交接草稿保留在忽略的 `.scratch/`，正式结论与实际结果以本记录和 ADR 为准。
