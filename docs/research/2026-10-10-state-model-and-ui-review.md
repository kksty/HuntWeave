# HuntWeave 状态与 UI 设计整理

日期：2026-10-10。本记录保存本轮取舍；实际要求落在 [ADR-0017](../adr/0017-claim-confirmation-and-frozen-delivery.md)、[状态与交付规格](../specs/0006-state-model-and-delivery.md) 与 [UI 规格](../specs/0007-research-workbench-ui.md)。来源为用户在本会话转交的 MiniMax/DeepSeek 评审、接受的 v5 和 Codex 随后的修正；不复制本机附件路径作为仓库依赖，也不把模型投票当成技术证据。

## 已吸收的设计

六维状态、按契约确认等级、服务端执行能力默认最终人工确认、lapsed 保留历史判定、有效性/保留分离、当前准入确定性失效、可见复审背压；研究图按服务组与分支泳道展示，执行/研究/复审/交付分别汇总，原始命令与证据可追溯。

## 原输入中必须校正的地方

| 原口径 | 采用的规则与原因 |
| --- | --- |
| unknown 只隔离 IP，不计全局物理额度 | 全局物理上限与每 IP 上限同时生效；停止未知仍计数。否则 4 个未停旧调用加 4 个新调用会超额。控制核对独立可用，结果未知但已停止可释放物理额度 |
| all_of 比 any_of 具有更高判定水位；每条析取支都必须证成 | 逻辑命题与证据/确认等级分开；一项真即可证明析取，整体证据不能自动确认子项，共享材料也不证明独立性 |
| 任一子项变化必须整体降级 | 必须重算、留版本；另一有效析取支仍满足契约可保留成立，避免过度阻断 |
| 未登记类型一律 supported | 是否有适用有效契约才决定确认；新方法不因未注册被封闭，无判据送独立审也不补足要求 |
| comp-fit 自动确认 | 仅机器可判定的组件/版本匹配事实可自动确认，目标可利用主张按实际后果类要求处理 |
| 人工主张确认是所有 confirmed 唯一入口；自动确认即可准入 | 主张按 auto/independent/human 分流，正式库保留独立推荐与人工确认门槛，自动阶段可结束待人审 |
| 证据失效强制 in_review 且自动运行 | 登记重审需求与当前失效；实际领取受预算/数据政策/Run 状态约束，不重开已结束阶段 |
| A2/A5 用一个枚举保存全部事实 | 复审阶段与各等级结果分别留存；引用、更正、争议可以并存，不覆盖已发生的事实 |
| dual_read 同时存两个可写权威值 | 兼容读以新轴为权威，旧来源值只作历史与漂移比较；确需双写另定事务与单一写入口 |
| 禁止事件作为重建输入 | 版本化业务记录是权威重建来源，事件仍可驱动增量投影，不把“非完整事件溯源”误读成不用事件 |

原 v3/v4/v5 的“唯一权威”“直接实现”“同 commit 落地”等交接措辞不进入产品规则。整理稿替换旧文档中的冲突语句，保留历史 ADR 和验证记录，删除重复状态列表及失效上限，不对代码或已有结果做全局 verified 替换。

## 实施边界

Phase 0 固定来源盘点、旧语义映射、兼容读、六轴引用、manifest 输入与默认等级。现有代码有调用/核对/证据，不具备完整 P2 结论实体；不能凭旧设计标签推造独立复审、人工裁定或准入数据。字段/版本归 P2-B/D、基础图归 P2-F、容量与两类长时验证归 P2-E，P1 顺序不变。

查询额度、渲染阈值、公平份额、复审保留比例、有效性/保留期限和 SLA 须按版本化配置与实际夹具校准。图查询与控制路径同库，有界池、超时、并发限制与物化减压，验收以有无图压力对照，不把 schema 当资源隔离，不承诺逐请求物理扫描量。
