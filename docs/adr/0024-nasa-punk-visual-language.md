# ADR-0024：视觉语言采用 NASA-punk 浅色设备面板

日期：2026-10-10。状态：已采纳，待实施。完整约束与验收见 [0009 视觉设计系统](../specs/0009-visual-design-system.md)。

前端视觉语言采用 **NASA-punk**：70 年代 NASA 规范手册的工程制图语言加浅色数据界面。底色 `#ECE5D6`，细线分面板并留出接缝与铆钉，全大写小号编号与方向标注，等宽或加宽无衬线字体，四色复古条或圆形任务徽章作为身份元素，**整幅只保留一个鲜艳强调色（红 `#D63A2C`）**，另加少量使用痕迹。禁止霓虹发光、全息投影与大面积渐变。

## 为什么值得记一条决定

安全工具的默认答案是暗色终端或 SOC 风格。选浅色设备面板是**刻意的偏离**，不记录下来会被后来者当作需要修复的不一致。而且它不是纯审美——它与既有约束同向：

- [0007](../specs/0007-research-workbench-ui.md) 要求**颜色移除后状态仍可辨识**、**禁止单一健康灯**。受限色板（尤其只有一种鲜艳色）天然阻止"用颜色编码状态"。
- 全大写编号与方向标注一旦编造，就直接违反执行可观测性的"不伪造"。因此这类标签必须绑定真实数据。

## 技术取舍

- **颜色只承载强调，不承载状态**；状态由文字、图标、位置与编号表达。
- 红色同时是"最重要"和"危险"的常见编码，两者必须可区分：**危险语义由警示斜纹与文案承担，不由红色承担**。
- **使用痕迹必须确定**（静态资源或固定 seed）：Playwright 视觉回归与浏览器验收依赖可重复渲染。
- **字体必须开源可分发**：Univers Extended 与 Helvetica 是商业字体，仓库不得打包其字体文件；使用 OFL 替代，商业字体只可作为字体栈尾部的本机回退。
- **装饰不得伪造语义**：分区编号、方向标注、警示图案都必须对应真实对象或真实含义。

## 后果

- 既有控制台（P1 [#19](https://github.com/kksty/HuntWeave/issues/19) 交付的 `RunConsole.vue` 与 `style.css`，当前是绿调浅色、圆角卡片、Inter）需要换肤。当前没有设计 token 层，色值散落在 54KB 组件里，因此**第一步是建立 token 层**，否则无法保证色板受控。
- 前端变更触发浏览器验收（[ADR-0018](./0018-backend-first-and-layered-validation.md)）；换肤需要一组"灰度高辨识"回归检查。
- 本决定不改变任何状态语义，不新增部署服务，不改变鉴权与执行边界。
