# ADR-0025：移除独立的研究深度档位

日期：2026-10-11。状态：已采纳，待实施。**部分替代** [ADR-0016](./0016-scheduling-and-resource-policy.md) 的深度档位条款；与 [ADR-0019](./0019-engagement-modes-and-policy-gate.md) 对齐。来源：[#36](https://github.com/kksty/HuntWeave/issues/36)。

移除作为独立产品配置的"研究深度档位"。当前基线里它只被描述为"表达研究深度"或"研究偏好与预算"，**没有档位取值、独立行为、程序判定或验收契约**，代码中也不存在对应字段或控件。留着它会让创建流程凭空多出一个与测试模式争同一语义位置的重叠控件。

各项行为回到明确归属：

- **测试模式**决定研究取向、可用能力与停止策略：覆盖面在完成某项主张的自动采证后停止该验证分支、其他检查继续；突破在有效授权与预算内持续推进本次约定的访问权目标。
- **突破不承诺无限运行**：目标满足、无可执行研究路径、预算或授权终止、取消分别按原因收尾。**首个成功留证不等于整个突破 Run 的完成条件**；具体目标完成判据归 [#31](https://github.com/kksty/HuntWeave/issues/31)，本决定不扩展攻击能力。
- **预算**表达投入额度。未来若提供"经济／标准"一类预设，它只是展示具体额度的便捷输入，**不再持久化一套影响权限或停止行为的深度等级**。
- **路径限制**（如"最多几跳"）若确有需求，应作为独立、可验证的路径限制另行定义起点、跳数计数与执行约束，不叫深度档位。
- **操作类别与范围**继续归授权策略；**证据判据与确认等级不随所谓深度变化**。

## 后果

- [0007](../specs/0007-research-workbench-ui.md) 的创建流程去掉"深度偏好"；[PROJECT §12.4](../../PROJECT.md) 改为由模式表达研究取向、由预算表达投入额度。
- 其他含义的"深度"不受影响：研究图查询深度、前提门嵌套深度、P3 的"深度与稳定性"。
- **不新增数据库迁移或空字段**。实施时若发现已有落地，记录实际受影响入口与兼容处理，不静默改写旧授权或 Run。
- 本决定是文档与 Issue 一致性清理，不改变现有预算数值、授权范围、真实执行门槛或 P1 顺序。
