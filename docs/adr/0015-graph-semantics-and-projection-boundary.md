# ADR-0015：研究图语义与投影边界

日期：2026-10-10。状态：已采纳，待实施（设计已确定，能力未实现）。细化 ADR-0009/0011/0014，保持六个 Module、`app/postgres/runner` 三常驻服务、PostgreSQL 与 LangGraph。主张与能力类判据见 [0005 规格](../specs/0005-capability-claim-criteria.md)，调度与资源政策见 [ADR-0016](./0016-scheduling-and-resource-policy.md)。

## 背景

用户要求：一个任务包含多个 IP，每个目标的研究过程可以像 BloodHound 一样成图并可视化，能看见尝试、转向与成功节点，点击节点看到实际命令与说明；同时必须考虑性能，并支持一次发布后 24×7 持续推进。

既有基线已经存在两层业务投影（服务事实关系与研究血缘关系，见 [P2 草案](../specs/0003-agent-research.md) 第 4 节）和玻璃鱼缸视图要求（总纲第 12 节）。本决定不新建第二份研究状态，而是补足把这些投影做成产品表达所需的语义与边界。

必须防止三类误读：把图当成执行依据或授权依据；把画布上的视觉确定性当成证据充分；把跨主机连线读成可以自动扩展授权范围。

## 决定

### 视角与职责

| 设计 | 所有权与约束 | 代价与收益 |
| --- | --- | --- |
| 三个视角：授权视图（Host）、服务视图（Service/入口）、Run 依赖视图 | 服务与入口是研究锚点；IP 页面是组合视图，不是独立模型轴；Run 视图表达跨研究项的依赖 | 避免以 IP 为主轴炸开多端口主机、隐藏同主机跨服务关系；视图数量增加，但每个视图的语义单一 |
| 研究项可绑定多个服务或入口 | 跨服务关系引用同一条业务记录，不在各服务子图复制副本 | 支持"用 A 的条件验证 B"这类研究，不产生第二份状态 |
| 调度、提交与状态跃迁仍归 `runs` | 视图只读投影与业务接口，不承担执行职责，也不排定顺序 | 公平性与队列事实只有一处真相；视图改动不会改变调度 |
| 命名固定为 Run＝运行、ResearchTask＝研究项、Attempt＝尝试，发布是动作 | UI 文案可以宽松地称"任务"，但进入模型上下文的文本由程序按规范词生成，不直接拼入界面文案 | 避免 Run/ResearchTask 混用渗入提示词与数据模型 |

### 主张契约

| 设计 | 所有权与约束 | 代价与收益 |
| --- | --- | --- |
| 必需维度＝通用要求 ∪ 能力类要求 ∪ 专用附加要求 | 专用契约可继承公共要求，不必重复填写；加载时校验**展开后的有效要求**，禁止覆盖、删除或绕过必需项 | 既允许复用，又能堵住"改名导致必要要求减少" |
| 通用要求固定包含目标归属、来源、证据片段、访问条件、反例处理与结论范围 | 所有主张一律适用，不因类型不同而省略 | 反例处理与归属不能靠类型选择回避 |
| 契约由 `runs` 持有，`harness` 只提建议 | 配置入版本控制，逻辑上属业务判定规则，与执行环境 profile 分开，Agent 不可修改 | 模型不能自行降低门槛；配置校验替代提示词约束 |
| 主张成立需要什么，与成立后能否入正式漏洞库，分两层 | 人工确认、严重性与准入继续按 [0004 规格](../specs/0004-finding-admission.md) 处理 | 图上的"成立"不等于入库条目，两者不共用一个标识 |
| 每次评估固定契约版本与输入版本；类型、必要条件或证据变化后重新评估 | 旧复审不能直接沿用 | 增加重评成本，避免陈旧结论借新证据存活 |
| 未登记类型仍可研究、记录证据，使用通用要求并显示缺口 | 结论停留在 `supported`；`尚无专用类型`、`证据不足`、`无法判定`是三个不同状态 | 保留未知方法研究入口，同时不给类型选择任何杠杆 |
| 分类不能只接受 Worker 标签 | 主张描述、所声称能力、证据与类型适用性一并进入独立复审；分类争议保留未决 | 分类未决不冻结独立合法研究，但依赖该未决分类才能判断可行性的后续动作须等待 |
| 程序校验要求与引用是否满足；证据语义是否充分仍由复审判断 | "字段填齐"不等于证明 | 程序与语义判断职责分开 |
| 绿色只表达"在明确范围内按有效契约成立" | 准入使用独立标识 | 避免视觉结果被读成入库或"无漏洞" |

### 前提门

| 设计 | 所有权与约束 | 代价与收益 |
| --- | --- | --- |
| `all_of` / `any_of` 结构化前提组，成员、版本、判定依据与当前状态一并保存 | 拒绝依赖环；叶子条件可以是确定性检查或引用带证据的语义判定 | 多前提不被路径查询替代，可逐项解释 |
| 三值逻辑：成立 / 不成立 / 未知 | `all_of` 中任一项不成立即不成立，未知与成立相与为未知；`any_of` 中任一项成立即成立，不成立与未知相或为未知；嵌套按同一逻辑向上传播，未知不得被父组吸收 | 避免"存在未知成员即不得成立"阻塞合法研究，也避免未知被吞成确定 |
| 区分"已被判定不成立"与"未知/待评估" | 两者渲染与状态不同 | `all_of` 中一项不成立表示当前前提组不成立，不自动意味着假设被证伪或永久不可恢复 |
| 前提状态可从成立回退为未知；失效证据不再证明其成员成立 | 退化必须触发依赖重评 | 需要可重算的门状态，不采用一次判定永久生效 |
| 是否需要重评依赖、是否取得有效研究进展，是两个判定 | 同一条件反复过期、刷新、再过期不得无限重置无进展计数 | 首次发现关键证据失效可以是有效认识；重复抖动不是 |
| `any_of` 成立时记录实际采用的有效成员及版本 | 重新派发时核验；成员失效时只重评依赖它的分支 | 恢复与唤醒可以精确定位，不波及无关分支 |
| 反例处理是独立强制维度 | 不能由任何 `any_of` 分支满足，与总纲第 11 节的关键反例条件一致 | 把"替代方案未知"与"存在未处理反例"两类未知分开 |
| 授权、预算、有效租约、取消状态与旧调用核对等执行硬约束不得成为前提组成员 | 前提组成员类型为闭合集合，**按类型在提交时强制拒绝**，不依赖提示词约定；派发前仍独立重校验 | 图上的"已满足"只是上一次评估结果，并标注评估时间与输入是否已变 |
| 边上的解释随版本保存 | 证据解释绑定具体片段；计划解释绑定 Decision 或前提记录；文本保持不可信来源标记 | 解释可追溯，且不取得指令或授权效力 |

### 尝试与证据关系

| 设计 | 所有权与约束 | 代价与收益 |
| --- | --- | --- |
| 尝试的语义身份＝研究问题（稳定标识）、目标绑定、相关访问条件版本、方法目的与判定条件 | 参数与命令、源码 hash、环境清单、执行实例、权限与网络模式留在 ToolCall 层 | 对照与变体请求参数不同仍属同一尝试；更换目标、关键访问条件或实质方法才产生新尝试 |
| 容器重建、普通恢复、同方法下预期的对照步骤不产生新研究节点 | 环境变化影响结果可比性时明确记录并重新评估 | 恢复可见但不污染研究图 |
| 实例重建在尝试内以可见徽章表达 | 可追到实际实例与调用；调用历史不因重建重置 | 与 ADR-0014 的身份分离一致，不产生虚假新节点 |
| 调用间关系分两维：验证用途（对照/探测/补证/独立复现）与执行关系（原始/后续/重试及关联调用 ID） | 两维可同时成立，不是互斥枚举；研究尝试中的调用应有明确用途，准备与采集等调用按各自契约表达 | 一条调用可以同时是对照与重试 |
| 角色声明不替代证据绑定 | 声明只表达预期用途，是否构成有效对照仍需校验 | 防止用标签代替证据 |
| 两个粗指纹：F1＝工具＋规范化参数，F2＝F1＋调用角色集合＋访问条件版本＋环境清单 | 仅用于查找前例与提示比较；不阻断调用、不合并证据、不复用结论；F2 不称为等价指纹 | 顺序会改变实验含义，故不以无序调用集合判定等价 |
| 尝试级结果用二元组表达：执行结果 × 认知结果 | 认知结果为支持/反驳/无法判定/不适用/受阻；执行结束但结论待评估记为执行已结束、结论待评估 | 退出码与结论彻底分开 |
| 执行已结束、结论待评估不得因模型不可用而阻止执行收尾 | 自动阶段结束前必须完成评估，或转为带原因的未决结束记录并撤销自动唤醒；晚到结果不自行恢复旧工作 | 避免"等模型"变成无限悬挂 |
| 部分证据可支持有限主张，不得推定整体完成 | 四维完整性分别表达：片段完整或截断、调用结果完整、尝试是否结束、实例停止与回收是否确认；**限制随引用传播**到图节点、发现与报告 | 局部事实可用，但不会被读成完整实验 |
| 结果未知不因已取得部分输出自动解除 | 仍须对账 | 与总纲第 8.4 节一致 |
| 进行中或结果未知的尝试中，已独立归档、来源明确的观察可被读取与分析 | 禁止冒充完整结果、推定成功或绕过核对重复未知动作 | 不冻结已取得的执行事实 |
| 去重区分三件事：相同方法、相同字节内容、相同采集事实 | 证据存储可复用字节，各次执行的来源与采集记录必须保留 | 与总纲第 11.1 节一致 |

### 归属与统计

| 设计 | 所有权与约束 | 代价与收益 |
| --- | --- | --- |
| 四类记录分离：服务绑定、覆盖记录、主锚点、成本归因 | 各自带规则版本与输入版本；都不从当前导航指针反推 | "绑定了服务"不等于"覆盖了服务"；用 A 的条件验证 B 只覆盖 B |
| 跨服务尝试采用单一记录、多处引用、指定一个主锚点 | 主锚点通常选择本次直接验证其能力或边界的服务；对称研究按规范化服务键确定性选定，人工可覆盖 | 多视图引用同一尝试，不重复状态 |
| 修改主锚点属版本化的导航归属调整 | 不产生新尝试、不重新计费、不改变历史覆盖、成本或结算记录 | 导航变化不追溯改写统计 |
| 确定性主锚点不防止重复创建尝试 | 重复提交由 `runs` 的统一提交入口、任务领取、提交幂等标识与重复检查处理；共享同一锚点的不同合法实验可以共存 | 去重依据沿用稳定研究问题标识与访问条件版本，不靠锚点 |
| 预算按调用、模型请求与准备工作各自的唯一记录结算一次 | 服务级成本分摊是派生统计，带规则版本，不得用于预算强制；共享开销保留在 Run 层 | 不在每张服务图重复扣账 |

### 投影边界与展示状态

| 设计 | 所有权与约束 | 代价与收益 |
| --- | --- | --- |
| 投影是只读派生，可从版本化业务记录重建并在同一水位核对 | 核对比较节点、关系与状态语义，不比坐标；投影落后时显示同步水位 | 不以事件溯源为前提；画布不是事实源 |
| 画布展示状态（缩放、拖拽、展开、筛选、固定坐标、选中）可本地保存 | 不调用 `runs`，不产生研究事件 | 交互流畅，不被业务版本检查阻塞 |
| 展示偏好与共享书签分开 | 本浏览器局部偏好；Run 级共享视图书签走业务接口、有版本与事件，但不得触发研究规划、模型调用或预算消耗 | 不引入个人账号语义（总纲第 9.3 节无账号体系） |
| 业务操作（暂停研究项、请求补证、更正关系、影响报告的标记、会进入模型输入或覆盖的"标为线索"）走对应业务接口 | 版本检查与审计事件；提交期间只显示"正在提交"；查看历史图时发起操作须重新核对当前业务版本 | 图不产生独立业务状态 |
| 模型上下文从结构化业务记录生成 | 规范术语由程序映射，不读取画布标签推断状态 | 展示层不能成为模型输入来源 |
| 租约过期但执行端未确认停止时显示"停止未确认" | 保留最后已知实例与调用，不得显示资源已释放 | 与总纲第 8.4 节、停止确认语义一致 |
| 图不回答预算、授权期限、整体费用与运行控制 | 这些放专门面板；节点详情可显示本尝试成本与阻断条件并链接对应面板 | 图只解释研究如何进行 |
| 队列解释展示当前事实：等待类别、等待时长、相关资源、实际占用者、恢复条件 | 等待类别为闭合枚举并与总纲第 12.2 节原因码对齐；占用者字段只反映持久事实，无确认持有者时显示未确认 | 不把等待全部压成"排队中" |
| 顺位与预计开始时间 | 顺位是某调度快照下特定可调度集合中的参考值，可能变化，不是承诺；预计开始区间为可选估计，附更新时间与不确定性，依据不足时显示无法估计 | 避免把公平调度误读成先到先得 |
| 覆盖缺口节点只能针对已登记范围、入口与研究问题派生 | 每项保存登记来源（授权端口集合、服务观察、已提交规划、Reviewer 补证请求）与来源版本；不能仅凭模型生成标题增加已尝试覆盖 | 不生成看似完整的"所有可能漏洞"清单 |
| 比例统一写作"在当前版本登记的 N 项研究问题中……" | 保留未尝试、阻断与排除原因；分母随范围版本变化，历史报告使用冻结分母；分母未知时不显示百分比；总量依据使用明确枚举（精确／估计／未知） | 完成比例永不作为安全分数 |

### 时间与冻结交付

| 设计 | 所有权与约束 | 代价与收益 |
| --- | --- | --- |
| 四类时间语义分开 | 目标返回时间属证据内容，标记来源与可信度，不用于权威排序；Runner 采集时间表达执行发生时间，跨实例不假定时钟一致；Run 发布 sequence 是默认时间线、增量同步与迟到事件的确定顺序；投影生成或读取时间只表达新鲜度与滞后 | 目标时钟不可信（总纲第 9.1.1 节）不污染顺序 |
| 默认顺序以 Run 发布游标为准，采集时间补充执行时间 | 迟到事件标记而不倒插发布游标；采集时间与发布序矛盾时保留矛盾、不重排 | 跨实例不伪造严格先后 |
| 跨 Run 不伪造全局序 | 默认并排比较，明确各自游标与对齐依据；可按采集时间提供近似对齐视图，但标注为启发式，不得创建证据绑定、不得进入结论或报告依据 | 与总纲第 11.2 节禁止按时间相邻猜测绑定一致；界面区分键匹配与仅时间相邻 |
| 默认时间轴与分支泳道布局 | 节点显示实际发生时间与持续时间；长时间等待可折叠但显示压缩标记，不把压缩后的横向距离当成真实耗时 | 顺序与结构同时可读，符合"阅读研究叙事"的目的 |
| 位置稳定性靠固定泳道、保留已有位置、只布局新增局部区域 | 全图重排是显式操作 | 位置种子只提供确定性，不保证已有节点不动 |
| 冻结交付的图修订标识含 Run、数据版本清单、筛选范围、快照制品与水位 | as-of 承诺边界：版本化业务记录为据、事件驱动增量投影、投影可从业务记录重建并在同一水位核对 | 区分"当时已知什么"与"现在如何解释过去的观察"；证据过期后标注不可核验，不声称可复现 |

### 查询与容量

| 设计 | 所有权与约束 | 代价与收益 |
| --- | --- | --- |
| 独立只读账号、有界查询连接池、查询超时与受控查询入口 | 投影 schema 用于职责与权限分离，但不隔离 CPU、磁盘与缓存竞争 | 隔离手段是资源控制与物化，不是 schema |
| 同时限制查询并发、执行时间、逻辑展开边数、深度、路径数量与返回规模 | 达到阈值返回明确截断原因，或提供带水位的物化快照；不无限重试直到查完 | 有界失败优于无界等待 |
| 逐请求可靠返回逻辑展开量、结果量、耗时、截断原因与水位 | 不承诺逐请求物理扫描量 | "数据库实际扫描多少行"不是低成本必返字段 |
| 物理工作量经采样执行计划（`auto_explain` 的 analyze/buffers）、基准与执行计划评估；容量观测使用 `pg_stat_statements` 的块访问与执行时间等聚合字段 | 指标含义必须标注：其 `rows` 是返回或影响的行数，不是扫描行数 | 避免用错误指标做验收 |
| 只有同一数据版本下完成完整计数才报告精确总量 | 水位是精确计数的必要条件之一，不是充分条件 | 受预算限制的邻域查询可能未遍历全部匹配对象 |
| 渲染路径：SVG 用于小图与静态导出，Canvas 用于交互主路径 | WebGL 仅在实测证明必要时引入，并与 Canvas 共享布局与交互契约；不按节点数机械切换（标签复杂度、边密度、更新频率与设备都会影响） | 控制维护路径数量 |
| 邻域与路径查询受深度与节点预算约束，超限显式截断 | 初始预算与阈值留实施期实测校准 | 限制返回量不等于限制数据库工作量，两者都要约束 |

## 明确不采用

- 不引入图数据库、图查询语言或第二套数据存储；路径查询与邻域查询在 PostgreSQL 上有界实现，且**路径查询结果不得替代前提检查**。
- 不引入完整事件溯源作为历史回放前提（与 ADR-0011 一致）；历史能力以版本化业务记录的 as-of 查询为界，超出该界的能力明确标注不可用。
- 不承诺逐请求物理扫描量，也不用当前加载数量冒称完整规模。
- 不把画布状态、节点颜色或布局坐标作为执行、授权或结论依据。
- 不为跨 Run 比较伪造严格全局序。
- 不为"看起来完整"生成通用漏洞清单或把完成比例当作安全程度。
- 不允许从图上一键跨授权展开目标；跨主机线索只作为线索显示，需人工纳入授权（总纲第 3.2、4.2 节）。

## 对既有决定的影响

- ADR-0009/0011 的规划权威、持久依赖与只读历史引用不变；本决定为其增加产品表达与投影边界，不改变 `runs` 是计划唯一提交者。
- ADR-0014 的会话、实例、调用身份分离继续有效；实例重建在图中以徽章表达，不产生新研究节点，也不重置调用历史。
- 总纲第 11.2、11.3、11.4 节的证据绑定、覆盖与准入规则不变；本决定只固定它们在图上的表达边界，能力类判据另见 [0005 规格](../specs/0005-capability-claim-criteria.md)。
- 总纲第 12.1 节的视图要求由本决定补足出口；第 12.3 节的结束条件新增一条约束：执行已结束、结论待评估必须在自动阶段结束前完成评估或转为带原因的未决结束记录。
- 总纲第 13.3 节的首批页面增加研究图页面；不与既有页面职责重复。
- 调度与并发政策不在本决定内，见 [ADR-0016](./0016-scheduling-and-resource-policy.md)。

## 实施归属

- 字段与版本契约（尝试、主张契约、前提门、覆盖记录、主锚点、成本归因、图修订）归 P2-B 与 P2-D，随 [P2 规格](../specs/0003-agent-research.md) 分片建立。
- 基础可视化作为独立切片（P2-F），不等待完整研究闭环，也不因此调整 P1 顺序。
- 容量与两类长时验证（合成夹具与加速事件、墙钟持续运行）归 P2-E；成对验收组与指标口径见 [P2 规格](../specs/0003-agent-research.md) 第 9 节。
- 渲染阈值、查询额度与邻域预算留实施期实测校准，配置版本化。

本决定只固定设计与边界，不表示任何图上能力、投影服务或可视化页面已经实现，也不创建实施任务或改变当前阶段状态。
