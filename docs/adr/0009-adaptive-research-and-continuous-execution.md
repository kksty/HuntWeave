# ADR-0009：证据驱动的任务规划与单次 Run 持续执行

日期：2026-10-09

状态：已采纳，待 P2 实现。初次决策时处于 P0-A/B，当前实现状态见 [STATUS](../STATUS.md)。规划提交权、持久依赖与证据版本由 [ADR-0011](./0011-planning-authority-and-evidence-revisions.md) 进一步明确。

HuntWeave 需要在已授权服务之间扩大研究覆盖，并在新证据出现时改变方法。保留 Python、LangGraph OSS、PostgreSQL 和独立 Runner，补充持久研究任务依赖、增量规划与上下文组织。**24×7 指操作员发布一次任务后，同一个 Run 在有效授权和预算内持续自主推进，完成后停止；它不表示周期性创建 Run。**问题、方案与验收依据见[架构改进研究](../research/2026-10-09-architecture-improvement.md)。

## 取舍

| 选择 | 收益与代价 |
| --- | --- |
| 保持 `Collector → Worker × N → Reviewer → 人工复审`，在 Run 内增加规划步骤 | Worker 保留局部方法选择；跨任务依赖、去重与资源分配有明确归属。增加任务版本及规划冲突处理，但不新增常驻角色或部署服务 |
| 服务事实、研究依赖与 LangGraph 执行图分别表达 | 事实可核查，研究路径可改变，检查点可恢复；三者用 ID 关联，不能把可视化图或模型待办当执行事实 |
| PostgreSQL 持久化 Research Frontier，harness 提出计划、runs 校验并应用 | 同一执行与授权入口承接规划，不另造任务引擎；需要验证过期计划、重复建议、依赖环和状态并发 |
| 按任务构建上下文，同 Run 共享有来源的观察；Reviewer 使用独立上下文和环境 | 降低重复研究及长对话污染；摘要需要版本、证据引用和按需读取，不能替代原始记录 |
| 单次 Run 持续自主推进，完成后停止 | 用户只需启动一次；需要明确可完成条件、持久恢复、资源上限与受阻状态。取消固定的四小时自动执行上限；任务授权有效期和预算仍由外部程序强制 |

现有 LangGraph 底座可以承接规划建议和会话上下文，runs 与 Runner 仍分别负责业务状态和真实执行。更换运行底座会重做检查点、接口和恢复契约，却不能单独解决范围限制、未知副作用或证据可信度。增加规划步骤也有任务版本、冲突处理和模型成本，因此须通过 P0 恢复与 P2 靶场评价验证收益，不预先宣称检测效果更好。

## 关键约束

- 规划是 `harness` 内部能力，只提出任务及依赖变更；`runs` 独占任务状态、授权校验、预算、租约和派发。规划步骤不直接执行工具、改授权或裁定漏洞。
- Worker 可自行换工具、研究新协议和方法；跨任务依赖及补充工作须落成持久任务。任务依赖表示前提，不表示可以根据发现自动扩展目标。
- 研究任务关系在现有 PostgreSQL 业务 schema 中按切片新增记录，按需投影成图；不增加图数据库、消息代理或向量库。LangGraph 描述会话推进阶段，不为每个协议或漏洞预编排固定路线。
- 通用 Shell、联网搜索和动态准备继续按总纲隔离。研究资料和共享观察都是不可信输入，来源更多不等于权限更大。
- 计划更新不重置已执行动作；`call_id`、持久意图、Runner 账本及对账语义优先于模型待办或图状态。结果未知的任务不能改名后再次派发同一动作。
- 24×7 是持续工作的能力，不是无限权限或必须始终占用模型/容器。排队、等待工具结果和有限退避保留同一 Run；服务重启后先对账再恢复。授权到期、预算耗尽、执行未知或缺少必要条件时明确阻断/结束，不自动扩大权限。
- 自动研究在可执行任务处理完毕、必要补证及 Reviewer 完成且在途调用真实收尾后停止。人工复审在自动阶段结束后处理结论，不成为每一步的运行门槛。自动研究完成或停止后不按周期重新扫描；以后明确请求复测可建立独立 Run。
- 正常顺序为自主渗透留证、AI 复审及有限补证、自动阶段结束与执行资源回收、人工复审。单独保存自动阶段结束时间、原因、复审完成情况与事实版本；研究等待和待人工复审分别展示。人工未处理不保留运行中的执行资源，复审不可用等例外明确记录未完成，不能假报 AI 复审通过。
- 等待原因、唤醒条件、重试计数、下次重试时间与截止持久化；重启或漏通知后仍能自动推进原任务。唤醒重新校验状态与授权，尊重主动暂停/取消和已结束状态，重复事件不重新消耗预算或派发动作。
- 完成判定包括未处理证据与规划、待派发意图、延迟重试、未知调用、复审和资源收尾；当前没有可领取任务不足以判定结束。任务新增/派发与结束提交按同一 Run 版本串行化，结束后拒绝迟到规划或唤醒重开执行。完整契约与验收见总纲第 12.3、14.1 节。

## 交付与检验

P0 验证确定性角色控制、持久假执行与同一 Run 恢复；其固定场景分支尚不证明根据工具结果研究，不提前创建完整探索关系。P1 完成通用目标执行与出口/回收隔离；动态准备与按需特权随 P2 交付。P2 按 [正式规格](../specs/0003-agent-research.md) 引入最小 Research Frontier、事件触发规划、任务上下文、覆盖报告及单次 Run 的自主持续闭环：用 Web/非 Web 对照证明不同证据改变后续任务、跨 Worker 不重复研究、重启后接续原 Run、Reviewer 独立反驳主张，任务结束后不再派发动作。P3/P4 扩大长时间靶场与故障注入，改进稳定性、资源增长和恢复质量；不推迟 P2 的持续闭环、基础备份恢复和数据保护验收。

详细契约以 [PROJECT.md 第 5、7、8、12、14 节](../../PROJECT.md) 为准。该决定补充 ADR-0005 的运行组织方式，不替代其 Compose、Kali 与工具保留选择。
