# ADR-0020：持久会话与最小实证边界

日期：2026-10-10。状态：已采纳，待实施。修订 [ADR-0012](./0012-minimal-proof-and-target-data.md) 的驻留表述与 [PROJECT §9.1.1](../../PROJECT.md) 的最小只读留证、[0005 C1a](../specs/0005-capability-claim-criteria.md) 的最低证明要求。决策依据见 [2026-10-10 双模式架构评估](../research/2026-10-10-two-mode-architecture.md)。

`breach` 模式允许受管的 `FootholdSession`：没有会话就没有文件传输、端口转发与交互式命令。**会话属于平台，不属于目标**——平台持有连接对象，租约绑定 Run，全部 I/O 进入证据，Run 结束或取消必须强制终止，不允许跨 Run 存活，不允许自启。

## 零驻留的确切含义，以及它不能证明什么

目标侧**零驻留**指：不写开机自启、计划任务、服务、账号。**但不得据此宣称目标无残留**：

- 目标进程**不受本地 Runner 的 cgroup 管理**。目标进程启动后网络中断，平台能关闭自己的连接与容器，却可能既无法终止它、也无法查询它是否退出。
- 即使最初不写盘，也不能证明目标系统没有产生日志、缓存等写入。

因此下列四类事实**分别记录，互不填充**：平台连接状态、平台执行资源停止状态、**目标侧进程停止证据**、目标新增对象。未知必须保留并限制后续动作，不能用本地停止事实充当目标侧的"无残留"。

同时必须分类"允许的最小新增"与"违规或意外副作用"：新增服务、配置、账号不能既被列为禁止，又被当作遗留对象登记。**"写了就记账"不能替代"哪一类是允许的"。**

## 最小实证边界的修订

原最小实证边界（取得身份、主机与时间留证后立即退出，不继续读取凭据、不提权、不驻留、不横向）**在 `coverage` 模式继续适用，并扩展到任何确认级证据之后**；它**不适用于 `breach` 模式**，否则该模式不存在。`breach` 仍受第 9.1、9.1.2 节的非破坏、测试新增数据记账与禁止删改约束。

[ADR-0012](./0012-minimal-proof-and-target-data.md) 的"不驻留"需要区分两种对象：**为完成本次验证而存在、随 Run 生命周期结束即销毁的会话**，与**驻留**。前者允许，后者仍禁止。

## 后果

- 长期会话如何占用主机锁、预算、恢复位置与停止确认，必须在实施规格中定义，不能只定义"驻留"这个词。
- 目标侧停止证据缺失时，该会话相关分支不得宣称已完成回收；停止确认语义沿用既有"已确认停止 / 未确认停止"的区分。
- 本决定不扩大任何实际目标的授权范围，也不放宽平台容器的隔离边界（目标机器上的提权属打法内容，平台容器内的提权仍是隔离边界且不开放）。
