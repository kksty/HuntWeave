# ADR-0003：单机首版的部署、存储与工具分层

日期：2026-10-08

状态：历史决策；SQLite、两个常驻容器及其执行身份相关选择已被 [ADR-0004](./0004-tool-lifecycle-runtime-and-observability.md) 替代，通用工具优先与协议适配器可选的原则保留。下文记录当时取舍，不作为当前数据库/部署要求。

## 问题

用户希望确认结构化验证工具的实际含义、通用工具与协议适配器的取舍、联网研究在 harness 中的归属，以及能否用单容器和 SQLite 简化部署。项目仍是单机、单组织、手动导入 IP、默认四个 Worker 的授权 Agent 安全平台。此前将 web、API、agentd、数据库和获取服务分别列为常驻服务，运维成本偏早。

## 决策

- 采用通用 Shell、文件、网络客户端与联网搜索为主的工具集合。协议适配器可选，优先封装反复使用、错误率高或需要稳定结果解析的能力；不要求先实现某协议插件才允许研究。
- 未预编排的方法属于首版研究能力：以 MSSQL 等实验环境为样例，Agent 根据实际访问条件自主查找方法、判断前提、准备脚本/客户端并尝试，保留结果与失败修正。适配器不是能力清单；新发现的账号/域名/地址作为事实线索，不自动扩大测试目标。
- “结构化工具”是有输入 Schema、执行代码、输出 Schema 与证据引用的可调用能力。Shell 本身也有结构化调用外壳；方法文档/skill 提供指导，不能代替执行代码。一个工具可以封装几步确定性验证，完整研究路线仍由 LLM 决策。
- harness 负责注册并调度 `search_web`、`fetch_source`、`prepare_tool` 等能力；搜索由可替换的外部搜索 API、供应商原生工具或 MCP 后端实现，不自建搜索引擎。下载与安装是另外的执行步骤，不因模型能搜索就自然具备。
- 首版采用 SQLite WAL、SQLAlchemy 与 Alembic。数据库保留任务、执行意图、检查点、认证会话和证据索引，证据正文放本地持久卷。一个活跃调度器，所有写事务保持短小，不在事务中等待模型或工具。
- 常驻部署收敛为 `app` 与 `runner-manager`：app 内同一业务代码包含 FastAPI、Vue 构建产物和 harness；API 与 agentd 是由进程管理器管理的两个进程。Runner 独立管理动态 root 工具容器，获取 Broker 是其内部受限模块，不强制成为独立部署服务。TLS 入口按部署配置，可复用已有反向代理。
- 保持两个信任范围：平台控制与密钥、Agent 可操作的工具环境。目标会话和洁净准备环境按需创建，并不常驻每种协议一个容器。提供一个 Compose 项目作为部署入口，不把“一次启动”解释为“所有东西共享一个 root 容器”。

## 代价与限制

SQLite WAL 支持读写并行，但同一时刻仍只有一个写入者，且不适用于共享网络文件系统。业务库保存在 Linux Docker 本地持久卷，不放在 Windows/WSL UNC、SMB 或 NFS 共享路径。开启外键、设置有界忙等待，短事务内以条件更新领取任务和预留预算；不使用 PostgreSQL 的 `SKIP LOCKED`。这些限制来自 [SQLite WAL 文档](https://sqlite.org/wal.html)。

首版数据库足够与否取决于实际写入量和锁等待，不能根据 Agent 数量或目标 IP 数量作绝对保证。出现多控制实例、多机调度需求，或合并日志写入与缩短事务后仍有持续锁竞争时，再迁移 PostgreSQL。ORM 只能减少迁移工作，不能消除 SQL 方言、迁移脚本和队列语义差异。[SQLite 适用场景](https://sqlite.org/whentouse.html)

单容器多进程可实现，需管理进程退出、重启、信号和健康状态。[Docker 多进程容器](https://docs.docker.com/engine/containers/multi-service_container/)。但把控制端与 Agent 的任意 root Shell 放入同一常规容器，会让平台文件、数据库和凭据失去所需隔离；同容器中换一个非 root 应用用户不能可靠解决。全局 Web 密钥只保护请求入口，不建立内部进程隔离。

被研究的网页、目标返回和仓库说明都是 Agent 的外部输入，攻击者无需访问控制台就可能通过这些内容尝试间接提示词注入；安装代码也可能直接执行恶意操作。本项目保持 root 工具自主性，同时隔离控制端资源，而不依赖“外部人员不能登录前端”来信任所有进入沙箱的代码。[OWASP 间接提示词注入](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html#remoteindirect-prompt-injection)

## 验证

实现后验证 API/agentd 同时写入、任务领取与预算竞争、重启恢复、WAL 检查点与一致性备份；测量锁等待和提交延迟。验证 app 与执行容器间无密钥、数据库或 Docker socket 泄露；证明正常 root 安装与自主工具调用可用。验证没有协议适配器也能完成非 Web 样例，增加适配器时用稳定性、成本或操作约束收益评估。
