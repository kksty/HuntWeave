# ADR-0016：调度、槽位与资源政策

日期：2026-10-10。状态：已采纳，待实施（设计已确定，能力未实现）。细化 ADR-0009/0011/0014；图语义与投影边界见 [ADR-0015](./0015-graph-semantics-and-projection-boundary.md)。保持六个 Module、`app/postgres/runner` 三常驻服务与单机 Compose；不引入多机调度、独立调度服务或第二套队列。

## 背景

基线已固定单 Run 导入上限 100 个 IP、Worker 会话并发 4、全局工具执行并发 4、同 IP 主动执行并发 1、单服务模型调用/工具调用 30/20 次，以及"同一 IP 主动执行默认串行"的约束（总纲第 8.3、12 节）。这些数值意味着：一个多服务主机在长时研究中会占用执行槽，其余主机可能长时间无法开始；同时"24×7"容易被读成"跑满 24 小时"或"所有 IP 都会被覆盖"。

本决定固定槽位归属、公平口径与控制路径保护方式，并明确哪些数值留给实测校准；不修改授权截止、预算与执行边界。

## 决定

### 槽位与并发

| 设计 | 所有权与约束 | 代价与收益 |
| --- | --- | --- |
| 按资源分池：模型请求、目标执行、准备与构建、复审各自独立额度 | 等待模型、搜索或准备时**不持有目标执行槽**；额度由 `runs` 统一协调，不由各会话自行计数 | 慢工作不再占住执行容量；需验证池间不互相堵塞 |
| 同 IP 主动执行并发维持 1 | 不放宽为 2：全局执行并发为 4 时，放宽只是重新分配，不增加总容量，且会让少数主机占用更多执行槽 | 保持既有主机锁与速率约束；容量问题先查槽位占用 |
| 研究项在调用结束后让出调度机会 | 模型等待、工具运行与准备工作不得绑定同一组槽位 | 这是吞吐问题的首选排查项，先于任何并发上限调整 |
| 受控复现与复审也计入同 IP 并发与全局额度 | 补证共用总预算 | 避免用"复现"绕过主机锁与预算 |
| 执行模式与并发上限沿用既有 profile 与部署配置 | 通用 Shell 不能自报"只读"以取得更大并发；需要更细约束时使用 `restricted-tools` 或相应适配器 | 与总纲第 9.1、12 节的工程限度一致 |

### 公平调度

| 设计 | 所有权与约束 | 代价与收益 |
| --- | --- | --- |
| 成本归一化：模型 token、目标执行秒数与准备耗时加权求和，权重版本化 | 调度前按**估算**成本预留，结束后按**实际**用量结算；三者的硬预算各自独立保留，不因归一化合并 | 公平以资源成本为单位，不以"尝试数"为单位 |
| 首触优先 | 仅作用于**前提已满足且资源可用**的主机集合，避免不可执行目标形成全局屏障 | 保证每个可研究目标获得基本研究机会 |
| 份额策略可校准，不使用固定比例硬门槛 | 其他主机均受阻时允许借用空闲份额 | "剩余预算固定比例"不适合作为每次动作的门槛 |
| 复审与补证保留处理能力 | 初始 20% 复审额度作为实验参数，实测校准 | 避免 Worker 用尽预算后没有能力审查结果 |
| 不使用固定先到先得 | 顺位只在某调度快照的特定可调度集合内表达 | 长时研究会饿死后段目标，故不采用队列顺序即公平 |
| 是否需要重新评估依赖、是否取得有效研究进展，分开判定 | 同一条件反复过期与刷新不得无限重置无进展计数 | 与总纲第 12.3 节"不能自动重置重试计数"同源 |
| 深度档位是产品配置（研究偏好与预算） | 不影响本次授权截止；授权、撤销、预算与截止仍独立强制 | 用户可用档位表达研究深度，而不是用墙钟时长 |
| 容量预期对用户可见 | Run 创建页展示按当前并发与档位下的完成预期，或明确提示可能超出授权窗口 | 不把 24×7 展示为覆盖承诺 |

### 队列可解释性与控制路径保护

| 设计 | 所有权与约束 | 代价与收益 |
| --- | --- | --- |
| 队列面板显示等待类别、等待时长、相关资源、实际占用者与恢复条件 | 等待类别为闭合枚举并与总纲第 12.2 节原因码对齐，例如等待目标执行槽、等待同 IP 调用结束、等待访问条件、等待依赖产物、等待预算、等待租约或对账、退避中 | 用户能判断等待类型，而不是只看到"排队中" |
| 占用者字段只反映持久事实 | 租约过期但执行端未确认停止时显示"停止未确认"，不得显示已释放或推断持有者 | 与总纲第 8.4 节一致 |
| 控制路径独立于慢工作 | 取消、续租、撤销、结果接收与对账不排在模型、搜索或环境构建之后 | 与 ADR-0014 的职责划分一致，不新增服务 |
| 图查询与 Run 控制共用一个 PostgreSQL | 图侧使用独立只读账号、有界连接池、查询超时与并发上限，必要时降级为读物化快照 | schema 与账号不隔离 CPU、磁盘与缓存竞争，须实测 |
| 负载验收采用对照测量 | 比较**有无图查询压力**时的取消响应、控制租约续租、预算事务与结果入库延迟，空载与满载差值须在验收指标内 | 查询够快只是其中一项，不能挤占执行控制能力 |

## 明确不采用

- 不放宽同 IP 主动执行并发，也不通过提高单主机并发解决吞吐问题。
- 不使用墙钟切片让权：单服务研究不设独立时长上限（总纲第 12 节），按时间片抢占会切断长时验证。
- 不使用固定比例硬门槛或固定先到先得作为公平口径。
- 不引入第二数据库、读副本、独立队列服务或多机调度；单机改为单调度进程，租约、去重与恢复语义持久化。
- 不把"24×7"实现为按时间或按 IP 数量的覆盖承诺。

## 对既有决定的影响

- ADR-0009/0011 的 Run 内规划与持久依赖不变；本决定只固定资源分配与公平口径。
- ADR-0014 的事务外模型调用、独立身份与控制路径保护继续有效；本决定把它落到槽位分池与等待类别上。
- 总纲第 8.3 节的"同一 IP 主动执行默认串行"、第 12 节的默认并发数值与预算表继续有效；本决定不修改这些数值，只规定它们的解释与公平口径，权重、份额与档位取值留实测校准。
- 总纲第 12.3 节的结束条件不变；等待与唤醒仍以持久等待记录为准，内存计时器与通知只作加速。

## 实施归属

- P2-A：模型在事务外运行、独立任务与会话身份，并验证慢模型不阻塞取消、续租与对账；同时验证研究项在等待模型或准备时不持有目标执行槽。
- P2-B：等待类别、持久等待记录与依赖释放；队列解释数据来源。
- P2-E：容量、长时运行与对照负载验收（含图查询压力下的控制路径指标）。
- P1 不受影响：#21 多活跃 Run 并发压力验收按既有顺序推进，仍使用既有票据、租约与取消契约。

本决定只固定设计与边界，不表示调度、公平份额、队列面板或压力验收已经实现，也不创建实施任务或改变当前阶段状态。
