# ADR-0021：范围语义与凭据复用

日期：2026-10-10。状态：已采纳，待实施。修订 [PROJECT §9.1](../../PROJECT.md) 的审批边界与凭据处理表述，细化 [ADR-0011](./0011-planning-authority-and-evidence-revisions.md) 的目标绑定。决策依据见 [2026-10-10 双模式架构评估](../research/2026-10-10-two-mode-architecture.md)。

`breach` 模式需要域内横向，因此范围语义从"IP × 端口"升级为**"主机集合 × 操作类别"**。授权不再只表达"哪些地址可达"，还表达"在这些地址上允许哪些类别的动作"。

## 凭据复用：校验通过后免批准，不是默认允许

同一授权内的多个主机之间，**凭据复用仍需逐目标 / 端口 / 动作校验**。这与既有的"邻域读取不授权探测，任何新的跨主机动作须逐目标/端口/动作校验"（[0007 §3](../specs/0007-research-workbench-ui.md)）一致：画布上看到一条凭据可用边，不等于可以拿它去打第二台。

校验通过后**不再要求人工批准**——它是同一台机器被攻陷后的自然延续，不是新的授权范围。校验不通过（目标不在授权集合、操作类别未覆盖、时间窗失效）走既有拒绝路径并给出结构化原因。

同时澄清两处既有条款的意图：不得**自动扩大**授权目标集合，不得**超出**操作授权。这两条不构成本 ADR 要修改的对象；本 ADR 修改的是最小实证边界与凭据获取/使用的授权语义。

## 可达性与第二跳

允许经授权主机转发，但**最终目标必须落在授权清单内，且由 Runner 侧校验并记录实际连接**，不接受模型声明，也不接受任意代理链。

**本地 Runner 校验第一跳，不能证明目标主机发出的第二跳受网关约束。** 因此第二跳的约束必须落在执行端可核验的事实上；无法核验时该分支只能标为未验证，而不是按"应该受控"记账。带外接收端与新传输面的完整决定见 [ADR-0022](./0022-out-of-band-receiver-and-transport-profiles.md)。

## 后果

- §9.1 审批表中"缺少的认证条件"与"目标扩展"的边界需同步修订，避免把授权内的凭据复用误判为需要补充审批，也避免把越界尝试混进预授权。
- 凭据作为观察/线索保存的规则不变；改变的是**使用**这些凭据时的授权语义，不是记录方式。
- 本决定不改变"不引入 SRC 归属或外部空间资产测绘"的产品边界，也不自动扩大任何 Run 的目标集合。
