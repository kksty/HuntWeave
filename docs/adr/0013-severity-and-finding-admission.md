# ADR-0013：标准严重性评分与独立漏洞库准入

日期：2026-10-09。状态：已采纳，待 P2 实现。行为草案见[漏洞评分与入库规格](../specs/0004-finding-admission.md)（未经评审；其在 P2 阶段表中的归属待补）。

用户要求过滤危害很小或无害的发现，避免版本提示等信息进入最终漏洞库。采用 **CVSS v4.0 严重性评分 + HuntWeave 入库策略 v1**：达到中危（≥4.0）只是必要条件，还须有实质安全影响、本轮充分证据、独立机器复审和人工确认。研究记录保留，正式漏洞库是通过门槛的 Finding 视图，不新增一份事实源。

选择公开、可复算的评分而非 SRC 奖励规则或自造加权分。CVSS 描述技术严重性，不能承担真实性、目标适用性或全部业务风险判断；因此分数与证据/裁定分开，未知信息不得当作无害。标准依据：[FIRST CVSS v4.0](https://www.first.org/cvss/v4.0/specification-document)。

## 后果

- 低危/无害信息不入库；仅版本/CVE 命中不入库。版本问题若取得实证并满足门槛，仍可成为正式漏洞，不能按标签全盘过滤。
- 评分必须有向量、逐项依据、算法与输入版本，模型不能任意报数或把多个低分相加；证据/环境/裁定变化触发重评，旧报告不能覆盖。
- 评分与“实际造成损害”分开。最小 RCE 实证可支持能力和影响判断，禁止为了评级扩大危害；测试新增数据和脏数据披露不受评分过滤。
- 补充 ADR-0011 的版本化结论和 ADR-0012 的非破坏验证边界；不引入 SRC、FOFA 或外部资产业务，也不提前改变 P1 已规划的执行范围。
