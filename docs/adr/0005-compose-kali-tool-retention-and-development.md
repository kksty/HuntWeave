# ADR-0005：Compose 部署、Kali 执行环境与选择性工具保留

日期：2026-10-08

状态：当前基线。用户将单/多容器取舍交由项目设计决定；本决策替代 ADR-0004 的严格单容器、统一 Debian 基础及所有动态环境进入长期工具库的方向。PostgreSQL、LangGraph、默认非 root/有限提权、玻璃鱼缸要求不变。

## 最终取舍

采用一个 Docker Compose 项目，三个常驻服务：`app`（Vue 静态资源、FastAPI、agentd）、`postgres`、`runner`。准备和目标工具容器由 Runner 按需创建；角色数量不等于容器数量。用户配置一次后从一个入口启动，无需手工逐个管理容器。不维护另一套单容器生产发行版。

平台、数据库与可执行第三方代码分开管理，以便独立控制隔离、升级和进程生命周期。[Docker Compose 应用模型](https://docs.docker.com/compose/intro/compose-application-model/)

## 基础镜像与权限

- app / runner：小型 Python + Debian slim 镜像；PostgreSQL 使用固定主版本及 digest 的官方镜像。
- 工具执行/洁净准备：以官方 Kali 镜像构建项目 tool-base，只安装选定常用工具。采用固定 digest 的 kali-rolling 基础并发布项目自己的已验证版本，不在生产中自动追踪 rolling 或每次启动全量升级。Kali 官方镜像并不自带全部工具。[Kali 官方镜像](https://www.kali.org/docs/containers/official-kalilinux-docker-images/)
- 普通研究 Shell 默认非 root。用户态安装不提权；系统包依赖可在不含目标数据/平台凭据的洁净准备容器中通过特权构建 profile 安装，生成任务私有执行环境或可保留 toolpack，目标执行重新以普通用户运行。
- Runner 的管理服务与可执行第三方代码的容器分开。只有 Runner 的受信管理进程接触所需 Docker 管理接口；构建/工具容器不获得 socket、host 网络、privileged 或任意宿主挂载。按需提权从执行票据进入受限环境，不是给 Agent sudo ALL。

容器需要应用、用户态文件与库，不需要另装一套带内核/桌面的完整操作系统；Linux 容器共享运行它的 Linux 内核。Windows/macOS 上的 Docker 通常通过 Linux VM 提供该内核。不能据此推断 Python 与动态安装工具适合空的 scratch 镜像。[Docker 容器概念](https://docs.docker.com/get-started/docker-concepts/the-basics/what-is-a-container/)

## 工具保留政策

默认先临时使用，只有高频、成本高或用户明确保留的能力才升级为可复用工具。分四层：预装核心工具、任务临时环境、限额短期缓存、选择性长期工具库。一次性 EXP 不自动长期保存完整环境。

每次真正执行成功且环境可复用时记录一次使用；一个任务内反复重试不刷高频计数。初始规则为同一工具/兼容环境在 30 天内至少 3 个独立 Run 成功使用时自动成为保留候选；Agent 可建议，用户可随时固定或删除，安装成本/体积/适用范围共同决定。规则可配置，无论文式最优保证。已满足保留策略的发布自动完成，不逐包重复确认。

短期下载/环境缓存有 TTL 和总空间配额，命中可以避免重装，未达保留标准的版本可被 LRU 回收。活跃任务租约优先于 TTL/配额；空间不足时清晰阻断，不能删除正在使用的环境。长期工具库只读、版本化，有体积上限；保留也不等于永久不可清理。OCI 层/包缓存尽量复用，但每个工具不必单独生成镜像。

工具的完整可执行环境与研究证据分别保留：一次性工具可删除大环境，仍保存来源、hash、调用/安装记录和结果。若要求可离线复现，明确固定必要的源码/依赖制品；否则显示可能需要重新下载，不能只凭 URL 宣称将来必可复现。

## 更新不绑定项目作者

上游维护者发布官方 app/runner/tool-base 镜像和兼容清单；每个部署管理员选择何时升级。下游可以使用公开构建配方在本地构建自定义 toolpack/执行镜像、选择自己的仓库或 fork 发布，无需项目作者逐次发版。Agent 任务内准备额外依赖也不等待作者，走隔离准备 profile。

平台更新、工具基线更新、任务临时依赖与 PostgreSQL 主版本迁移是四个独立操作。运行任务固定镜像/工具版本，更新面向后续任务；先排空或明确中断受影响运行，再做有备份的部署升级。禁止自动全量升级活跃平台、混合 Kali 软件源到 app 镜像或隐式升级 PostgreSQL 主版本。

## 验收

Compose 从全新配置启动，数据库/工具独立升级，动态容器可回收且不获得平台秘密；普通用户可以自主准备新依赖；一次性 EXP 的大环境按期清理；高频工具正确提升/复用、活跃版本不被误删；下游无需修改平台源码即可构建自定义 toolpack；所有保留、删除、缓存、构建及更新决定可在玻璃鱼缸查看。
