# ADR-0017：主张确认、当前有效性与冻结交付

日期：2026-10-10。状态：已采纳，待实施。依据本轮用户接受的 v5、默认确认等级及随后确认的修正。细化 [ADR-0011](./0011-planning-authority-and-evidence-revisions.md)、[ADR-0013](./0013-severity-and-finding-admission.md)、[ADR-0015](./0015-graph-semantics-and-projection-boundary.md) 与 [ADR-0016](./0016-scheduling-and-resource-policy.md)。不改变六个 Module、技术栈、部署服务或 P1 顺序。

把执行完成、证据支持、复审、人工确认和正式入库压成一条成功阶梯，会使等待或资源故障改写研究结论，也使历史确认被误读为永久有效。因此分开记录六个维度：主张判定、复审、尝试生命周期、准入、证据与资源；`runs` 统一提交版本化业务变化，投影只读。

主张按契约的 `auto / independent / human` 确认等级成立。默认服务端执行能力须人工最终确认，其他能力类须独立 Reviewer；可机器完全判定的组件/版本匹配事实可自动确认。该等级不增加已授权最小实证的执行前审批。正式漏洞库继续同时要求实质影响、充分且当前有效的证据、中危以上评分、独立复审推荐与人工确认，不因主张可自动确认而放宽。

历史判定与当前有效性分离。必要依据失效时保留原 verdict，附 `lapsed` 及原因，当前准入立即失效；重审记录可持久登记，但模型调用与目标补证仍须有效预算、授权和 Run 状态，不能自动重开已结束的研究。冻结只固定交付输入，不豁免输入有效期；保存期限与有效期分别记录。

`all_of / any_of` 表达逻辑命题，不表达置信度或投影水位。析取成立不证明每个子项；同一原始证据可经独立绑定支持多个主张，不构成多来源或独立复现。输入变化触发重评，有其他有效依据时允许保留整体成立并记录新的评估。

控制槽释放不证明进程停止。全局物理执行上限与单 IP 上限同时生效；结果未知但停止已确认可释放物理额度，停止未确认则继续计数。容量耗尽时目标执行可背压，核对、取消与回收仍须可用，不以超额启动其他 IP 消除等待。
