# ADR-0004：工具复用、按需提权、单容器交付与透明执行

日期：2026-10-08

状态：部分历史。其严格单容器、统一 Debian 基础和动态环境普遍持久保存的方向已由 [ADR-0005](./0005-compose-kali-tool-retention-and-development.md) 替代；PostgreSQL、LangGraph、默认非 root/有限提权及透明执行原则保留。以下记录 0.5 时的取舍，当前部署以 PROJECT.md 和 ADR-0005 为准。

## 背景

用户要求避免重复安装工具，改为默认非 root、按需提权；数据库明确改回 PostgreSQL。用户希望一个 Docker 即可运行，并将测试过程、阻断原因和中断恢复像“玻璃鱼缸”一样展示。本轮按严格单运行容器设计交付，明确其隔离边界与代价，不把取消 root 解释为已经安全。

## 决策

1. **工具持续复用**：基础镜像提供常用工具；持久化工具库按工具版本、源码 hash、依赖锁、基础镜像/ABI 与 CPU 架构存储。命中时复用或从完整环境快照快速实例化，任务目录仅保存可写工作状态；任务结束不卸载共享工具。下载缓存与可执行环境缓存分开，不能只缓存包文件却声称无需重新安装。
2. **更新产生新版本**：新版本在准备区构建并测试，原子发布到工具库。Run 固定工具与环境清单，运行中不替换；失败回退旧版本。常用且稳定的工具进入下一版基础镜像，Agent 不能自行覆盖共享默认版本。垃圾回收只清理超过保留期、无活跃租约且没有保留引用的版本。
3. **默认非 root、按需提权**：Agent Shell 使用会话专用普通用户。用户态包、虚拟环境和编译优先不提权。`request_privilege` 请求一次具体操作；已有策略覆盖的自动执行，超出权限的才等待用户。若提供 sudo，只允许调用 root 所有且 Agent 不可修改的窄 helper；其参数为执行票据 ID，不允许 sudo ALL、shell、解释器、编辑器或通用包管理器入口。系统包安装脚本能执行代码，因此不属于天然安全的白名单动作。
4. **单容器部署**：一份镜像运行进程管理器、FastAPI/Vue、agentd、执行管理进程及 PostgreSQL；API、编排、数据库、工具使用不同 UID 和受控目录。只暴露 Web 入口，数据库使用受保护的本地 Unix socket。数据、证据、工具库通过具名卷持久化。会话使用独立工作目录、用户和经验证的进程/文件/网络沙箱；实际隔离需要实现验收，不以“一个普通用户”替代。
5. **权限能力限制**：单容器不提供宿主 Docker socket、host 网络或 privileged 模式。默认工具进程不持有额外 capabilities。需要系统依赖时先使用已固定版本的用户态工具包；确需修改系统包的，由维护流程重建下一版基础镜像。任意 root 安装脚本不能通过 helper 修改正在运行的平台环境。受限提权先实现有限的管理动作；更多能力按实际工具需要及隔离验收扩充。
6. **系统基线**：采用 Debian 13 slim / trixie 系列并固定镜像 digest；运行库和工具依赖均做兼容性验收。不以 Kali 全量安装或滚动升级作为默认运行环境。[Debian 发布信息](https://www.debian.org/releases/stable/)
7. **数据库**：PostgreSQL 承载领域数据、持久任务/事件及 LangGraph 检查点，逻辑 schema/账号分开。应用与数据库升级有独立迁移、备份与恢复步骤，数据库主版本不能随应用镜像静默更换。
8. **harness**：采用 LangGraph OSS 作为检查点、暂停恢复与事件流的底座，本项目实现领域层、ToolRegistry、Runner、PolicyGate、工具版本管理和玻璃鱼缸 UI；不依赖 LangSmith 云服务。四角色和开放式研究循环保持，图节点不按漏洞方法逐一硬编码。[LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence)、[暂停恢复](https://docs.langchain.com/oss/python/langgraph/interrupts)、[事件流](https://docs.langchain.com/oss/python/langgraph/streaming)
9. **透明执行**：任务树、依据摘要、搜索来源、实际命令/参数、输出、工具安装/缓存命中/更新、提权、预算、检查点、阻断与恢复均由真实事件驱动。持久事件支持断线补拉和审计，敏感字段脱敏；不要求暴露模型内部思维链，不编造未提供的阻断原因或进度百分比。

## 框架取舍

完全自研可以精简依赖，但用户新增的持久暂停、多 Agent 状态、实时事件和恢复要求使其重复建设成本上升。LangGraph 适合此次需求，采用它不等于自动获得安全沙箱或副作用恰好一次执行。Pydantic AI 是类型化工具/Agent 的候选，完整耐久执行另有后端集成；本轮不同时叠加两套循环。它们谁更好取决于需求，本决定需在 P0 用故障恢复小样验证。[Pydantic AI 耐久执行](https://pydantic.dev/docs/ai/capabilities/durable_execution/overview/)

LangGraph 恢复中断时可能重新执行节点开头的代码。所有外部副作用仍以唯一 call_id、持久意图、Runner 去重和结果对账管理；不得把模型调用、安装和目标执行塞进一个大节点，再依赖框架重跑。

## 单容器与提权的实际边界

非 root 降低文件和进程访问权限，无法防止进程滥用其已有网络权限，也不能证明下载代码无害。不受限 sudo 会恢复任意 root 能力。单容器各进程共享更大的故障和内核边界；工具用户隔离、目录权限、数据库连接认证和执行沙箱需要实测。若宿主不支持设计所需的沙箱/网络能力，启动自检应说明缺失项并阻止相应主动执行，不能静默变成无限制运行。

不为凑单容器数量在内部启动 Docker daemon，也不以 privileged 绕开隔离困难。需要更强隔离时可以后续增加独立执行容器或独立主机部署方式；当前交付目标仍为单容器。

## 中断与安全围栏

区分模型服务拒绝、平台策略拒绝、权限不足、来源不可用、依赖失败、限流/配额、预算耗尽、人工暂停、取消、网络故障和执行端丢失。显示来源、可用的实际说明、受影响步骤、是否已执行、现有证据、能否重试及恢复条件。只在可安全重试时有限重试；不通过隐藏拒绝、改写提示词或自动轮换模型规避模型服务限制。用户授权能调整本平台的配置范围，不能保证第三方模型必然接受任务。

## 验收

- 同一工具/环境重复任务命中缓存，无无谓下载/安装；更新不改变正在运行的版本，回退与回收正确。
- 普通工具和用户态安装无 root；受限 helper 不能启动任意 root shell、篡改平台文件或执行任意 root 包安装脚本。
- 全新部署只有一个运行容器、一个业务入口，具名卷保留 PostgreSQL、工具库和证据；停机恢复与数据库迁移可演示。
- UI 可追踪每个 Agent 的真实动作、等待、失败及恢复；断线后补拉完整关键事件，敏感信息不泄漏。
- 模型拒绝/策略阻断/执行结果未知有不同状态；中断恢复不重复未知副作用，不假报成功。

本次仅调整文档，无已运行的镜像、数据库、sudo 配置或 harness 实现。
