# ADR-0018：后端先行、集中前端接入与分层验证

日期：2026-10-10（Asia/Shanghai）。状态：已采纳。依据本轮用户要求：开发聚焦安全测试与研究，先完成后端能力与接口，随后集中完成前端接入，最后进行浏览器验收。保留既有 Python/FastAPI、Vue、六个 Module 和三常驻服务。

后端阶段以当前正式规格为范围，交付 API 契约、响应样例、状态及原因码、数据库迁移、Runner 执行与证据、取消和恢复等实际行为。用对应的单元检查、API/数据库集成检查及本地靶场探针验证；后端逻辑的正确性与退出条件可以独立于浏览器判断。前端尚未接入的能力明确记录，不能把后端检查通过写成整个平台完成。

后端接口与必要行为稳定后，再集中实现对应 UI 规格并接入真实 API。前端类型检查和构建验证源码，浏览器验证登录、页面交互、事件展示与完整用户流程。前端变更、已进入对接阶段的接口变更或阶段最终验收触发相关浏览器检查；纯后端迭代使用后端验证。阶段退出与真实执行开放仍满足既有规格和 ADR-0010 的全部门槛。

联调前保留契约与固定响应夹具，覆盖未就绪、unknown、停止未确认、版本冲突、证据缺失等必要状态；避免前端最后接入时依赖后端临时猜测字段。浏览器定位故障时先运行能复现问题的单项或小组，修复并通过后再做必要的集成验收。前端构建在前端源码或构建配置变化时执行；仅测试脚本变化时做类型检查与相关测试。

Web 入口保持单个全局 Key，由服务端校验并以会话维持登录。密钥提交即时校验，错误次数不产生锁定或等待窗口。公网入口的额外请求控制由部署者按需配置，不是本项目开发或启动的前置条件。服务端鉴权覆盖业务 API、事件与证据；执行授权、隔离、预算及证据约束继续按正式规格验证。

此选择减少后端开发被 UI 环境和浏览器等待拖慢的成本，代价是界面交互问题集中到对接阶段发现，因此提前固定契约并保留失败状态夹具。取舍依据见 [开发与验证边界评估](../research/2026-10-10-development-and-validation-boundaries.md)。执行约定由 [AGENTS](../../AGENTS.md) 引用，命令与测试等待参数维护在 [README](../../README.md#验证)，实际验证结果写入 `docs/validation/`。
