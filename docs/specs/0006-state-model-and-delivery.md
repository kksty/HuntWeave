# P2：状态、确认等级与冻结交付契约

状态：设计已确认，待实施、未验收。日期：2026-10-10。依据用户接受的 v5、默认映射与后续修正，以及 [ADR-0017](../adr/0017-claim-confirmation-and-frozen-delivery.md)。本规格固定业务行为与迁移输入，不宣称数据库迁移或 UI 已完成。能力判据见 [0005](./0005-capability-claim-criteria.md)，准入门槛见 [0004](./0004-finding-admission.md)，交互见 [0007](./0007-research-workbench-ui.md)。

## 1. 六个独立维度与唯一写入方

六轴是领域维度，不要求一轴一表；禁止把不同维度折成一个状态字段。`runs` 校验并提交业务变化，Runner 提供执行与停止事实，evidence 管理材料，timeline 派生展示。

| 轴 | 对象与取值 | 必须分开的事实 |
| --- | --- | --- |
| A1 主张判定 | 固定 `claim_id / claim_version` 的评估：`undetermined / supported / refuted / confirmed`；另有 `lapsed` | 曾经如何判定与当前是否仍有效 |
| A2 复审 | Review 及其结果；确认等级、人工决定、分歧与排队记录 | 程序校验、独立复审、人工确认可以同时存在，不能用后者覆盖前者 |
| A3 尝试 | `active / awaiting_model / awaiting_prep / blocked / terminated_for_constraint / ended`，另记结束原因与执行结果 | 尝试结束、单次调用完成与主张成立 |
| A4 准入 | 绑定 Finding 与完整输入版本：`pending_review / admitted_current / exited_invalid / revoked / expired` | 主张成立与正式入库 |
| A5 证据 | 采集/引用/争议记录、保留保护、有效期、保留期、可读性与完整性 | 保存、可读、当前证明适用性 |
| A6 资源 | 模型/搜索/准备/复审/控制槽、全局物理额度、同 IP 占用；IP `normal / quarantine / degraded` | 逻辑处理结束与物理执行停止 |

工具完成、证据要求满足、独立复审完成、人工确认、当前准入必须可分别查询。`satisfied` 是对固定契约和输入版本计算的谓词，不是 A1 状态；保存评估输入、结果和缺口供审计，不把缓存结果当成永久依据。投影水位只表示同步进度。

## 2. 主张与判定

主张固定内容、条件、目标绑定、能力范围与版本；判定记录至少保存输入版本清单、有效契约/判据版本、结论、支持/反例绑定、缺口、评估时间和来源。新判定追加记录并经版本检查更新当前引用，不覆盖历史。

| 迁移 | 必要条件 |
| --- | --- |
| `undetermined → supported` | 已取得可引用的支持证据；无证据不能仅凭模型意见升级 |
| `supported → confirmed` | 展开后的有效要求满足，达到 §3 确认等级，必要输入当前有效 |
| `undetermined / supported / confirmed → refuted` | 反例证据、明确条件及被反驳的主张版本齐备；经适用判据评估 |
| `confirmed → supported` | 显式 `downgraded_to_supported` 记录，列出缺失要求及新依据 |
| 依据失效 | 保留历史 verdict，设置 `lapsed`、原因及时间，取消当前有效资格，登记重审需求 |

`supported` 表示已有支持，尚未达到完整确认要求。缺口区分证据、适用判据、确认等级等；证据齐备但待人工时可没有证据缺口，仍有确认等级缺口。工具失败、方法不适用、缺凭据或到期不反驳主张，只改变尝试或控制状态。

`confirmed` 引用 A2 的确认记录（`confirming_review_id`）及主张/输入版本、时间、实际达到的等级；人工决定由该 Review 关联。A4 单向引用主张评估、Review、HumanDecision 等版本，A1 不引用 A4。一次人工操作可以同事务产生确认与准入评估，但两者分别校验，不产生相互依赖的确认环。

当前成立谓词要求 verdict 为 `confirmed`、未 `lapsed`、必要输入有效且无未处理关键反例。历史 `confirmed + lapsed` 不计为当前成立，不在图上保持无条件绿色。失效不是证伪；读接口须实时检查有效性，不能等后台更新标记才排除失效结论。

## 3. 确认等级与复审

### 3.1 默认映射

`required_confirmation_level ∈ {auto, independent, human}` 由版本化契约规定，模型不能修改。默认映射如下；契约覆盖须作为明确的规则版本变更审核，不能由一次研究建议降低等级。

| 主张类别 | 默认等级 | 边界 |
| --- | --- | --- |
| `exec-cap(server)` | `human` | 最终主张确认须人工；不增加已授权 RCE 最小实证的前置审批 |
| `exec-cap(browser)` | `independent` | 受控浏览器上下文中的执行，不按服务端身份/主机留证误判 |
| `authz-fail` | `independent` | 身份、动作、对象与权限边界须核查 |
| `injection` | `independent` | 机制与实际后果分别判定，必要时叠加执行类要求 |
| `info-disc` | `independent` | 实际片段、范围及非公开性/敏感度须核查 |
| `misconfig` | `independent` | 配置事实与影响推导分开 |
| `comp-fit` 的组件/版本规则匹配事实 | `auto` | 仅机器可完整判定的匹配事实；不是本目标可利用能力的确认 |
| `comp-fit` 的实际可利用主张 | 按后果类，至少 `independent` | 服务端执行后果沿用 `human`，不可通过改名降低要求 |

无专用类型但有适用有效通用/能力契约，可按该契约确认，不限制新方法。没有适用有效契约时默认送独立复审以澄清分类和判据，但不能因此确认；已有支持证据可为 `supported` 并标“验证要求未明确”，没有支持证据为 `undetermined`。

### 3.2 流程记录

Review 分开保存 `level`、处理状态、结果与输入版本。处理状态为 `requested / in_review / completed / on_hold`；结果分别保存程序 `auto_reviewed`、独立 `independent_reviewed` 与推荐结论、人工 `human_confirmed` 或退回/未决。`disputed` 表示评估分歧，`sla_escalated` 表示升级标记，不替代已完成的复审事实。独立 Reviewer 使用与产出方解耦的上下文；重新执行还须独立实例与工作区。

满足证据要求后可按输入版本去重创建确认流程；缺证据、分类争议和失效重评也能入队，但注明目的，不能因 `satisfied=false` 丢掉重审需求。各阶段耗时分别记录。超 SLA 只能提醒或升级处理，不能自动 confirmed。

**队列目的与不得死锁**（[0008 §3.5.2](./0008-coverage-mode.md)）：队列至少区分五种目的——`confirm`（确认复核）、`evidence_gap`（缺证）、`classification`（分类澄清）、`lapsed_retest`（失效重审）与 `retest`（打回复测），各有独立入口条件与退出路径，**任一目的不得阻塞其他目的**（入口条件、允许动作与退出路径以 0008 §3.5.2 的表为唯一来源）。三个概念必须分别可查询、互不替代：**「证据要求已满足」是对固定契约与输入版本计算的谓词**（不是 A1 状态，见 §1）、**「确认级就绪」是分流候选状态**、**`confirmed` 是达到契约确认等级的 A1 判定**。因此「证据要求已满足但确认等级未完成」是正常中间态：**自动采证不等待人工**，停止的是已完成采证的那条验证分支，不是整个 Run；把等待人工实现成不能继续采证即构成死锁，属验收不通过。

队列不静默丢弃。`runs` 维护版本化队列容量/背压策略、待处理数、最久等待及分等级分桶；达到资源上限时明确暂停领取或生产相关工作，保留未决摘要。策略配置不塞进已冻结 manifest；交付可固定当时的队列快照引用。等待人工不占目标执行槽，不阻止独立研究或自动阶段收尾。

## 4. 尝试、调用与完成

Attempt 身份由稳定研究问题、实际目标绑定、相关访问条件版本、方法目的与判定条件确定；调用命令/参数、脚本 hash、环境清单、实例和网络模式留在 ToolCall。对照参数变化、合法瞬态重试、实例重建不必新建尝试；关键条件或实质方法改变才建新尝试并关联旧尝试与转向原因。

调用记录验证用途（对照/探测/补证/独立复现）与执行关系（原始/后续/重试及关联调用）两维；用途标签不替代 EvidenceBinding。F1 工具/参数指纹与 F2 加用途、条件及环境的候选指纹只提示比较，不阻断调用、不合并证据或复用结论。统一提交、领取与提交幂等防止重复；未知调用不得通过新 Attempt 绕过核对。

`blocked` 表示缺研究前提；授权/预算/取消等导致终止记 `terminated_for_constraint + end_reason`，不改变 A1。租约暂失、等待旧调用核对不自动结束尝试：先阻止派发、保留调用与停止事实，按核对结果决定继续或受限终止。已终止尝试不复活；后续明确恢复工作须关联新尝试并重新校验，不能清零重试、成本或未知历史。

执行结果与认知结果（`supports / refutes / inconclusive / not_applicable / blocked`）分开。认知结果须引用观察/证据或结构化限制；没有充分依据保持 `inconclusive`。Collector、环境准备、Review 和报告各有记录，进图用各自类型，不伪装为研究尝试。

部分证据可支持有限主张，四维限制随引用到图、Finding 和报告：片段完整/截断、调用结果完整、尝试是否结束、停止/回收是否确认。已归档观察在运行中或结果未知时仍可读；不得推定整体成功、已停止或可重复未知动作。

`execution_closed / conclusion_pending`、分类未决及自动复审未完成均进入未决工作。自动阶段结束前评估完成，或持久化带原因的受限结束记录、撤销自动唤醒与未派发意图。结束提交固定完成规则版本、事实/任务版本与已处理触发水位，和新增工作在同一 Run 版本约束下串行化；提交前已到达的有效工作必须参与。迟到原始执行证据仍归档对账，形成修订；迟到模型建议不得自行重开自动执行。

## 5. 证据与时效

不可变原始证据由执行层采集，模型只能引用。`proposed` 仅是采集计划，不可作已取得证据；归档成功为 `collected`。`referenced`、`superseded`、`challenged` 为可同时存在的引用/更正/争议记录，`gc_pending` 为回收流程状态；不要强制单一枚举吞掉这些事实。

证据至少分别保存可读性/缺失原因、四维完整性、有效性依据与 `validity_until`、保存策略与 `retention_until`。有效性约束针对证明用途及目标条件；原始材料过了适用期仍可作历史观察，不能把过期解释为过去未发生。时效由明确契约定义，不能因保留 30 天推造 30 天证明有效期。

`reserved` 表示存在有效的保留保护引用，由版本化保护记录派生；不证明证据仍有效。冻结交付的保护持续至约定保留期限或显式固定保护解除，不能因冻结永久禁止回收。多个保护引用逐一核对，单个 manifest 到期不删除其他引用仍保护的字节。保留期限届满后按策略回收，索引、历史判定与缺失原因保留。

必要输入失效 → 相关主张 `lapsed` → 幂等登记 A2 重审需求 → 当前准入失效。登记不等于正在审，也不授权模型费用或目标调用；自动阶段已结束时等待明确请求，仍可确定性刷新有效性。冗余非必要辅助证据过期只触发影响评估，有其他满足契约的依据时可保留当前成立并记录新评估。反例出现立即取消无反例条件的成立资格，但反例须经判据判定才产生 `refuted`。

## 6. 准入与当前有效性

准入绑定 Finding、主张评估、证据集合及绑定/片段/hash、评分、程序/独立 Review、HumanDecision、契约/判据/准入政策版本。完整门槛唯一来源为 [0004 §3](./0004-finding-admission.md#3-入库必须同时成立的条件)。主张确认等级为 auto 或 independent 也不能省略正式入库的独立推荐与人工确认。

状态迁移：`pending_review → admitted_current` 须全部门槛满足；必要输入失效进入 `exited_invalid`；人工撤销进入 `revoked`；manifest 整体有效期届满进入 `expired`。重评创建新的输入版本评估，原准入、历史人工决定和报告保留。

当前准入读取按完整输入和当前有效时间确定性计算，不依赖清理任务是否跑过。缺文件/hash 不符、必要证据失效、关键反例未决、主张失效、契约/判据失效、准入政策变更、必要评分/复审/人工输入过期或版本不匹配均阻止当前有效准入。原因使用闭合枚举，例如 `evidence_expired / evidence_unavailable / counterevidence_pending / claim_changed / contract_invalid / criteria_invalid / admission_policy_changed / assessment_invalid / review_invalid / human_decision_invalid / manifest_expired`，保存具体输入引用；多原因可同时列出。

规则发布新版本不必抹除历史；其兼容/失效政策须版本化。历史与当前分区计数可见，不能通过默认隐藏失效条目掩盖退出原因。

## 7. 资源、核对与背压

沿用 [ADR-0016](../adr/0016-scheduling-and-resource-policy.md)。全局物理执行上限默认 4，同 IP 主动执行上限默认 1（跨 Run，受控复现也计入）；控制派发槽初始 4，独立记账，不等于物理额度，管理处理不等待该派发槽。派发前在短事务内同时预留预算、调用/意图、物理额度和全部实际 IP 的占用，失败全部不领取；多 IP 规范排序获取，避免相互等待，不按主锚点只锁一个 IP。

等待模型、搜索、准备时不持有目标执行额度。目标调用在叶子资源阶段运行，不持长事务、不反向等待模型/准备。结果接收、续租、停止、核对与回收有独立控制处理能力；控制槽幂等释放，资源账本与预算各自结算，任一结算不得重复释放。

结果结算、超时或租约过期可结束对应控制处理；**只有可信执行记录证明该调用及残留进程/连接已停止，才释放物理额度与同 IP 占用**。结果 unknown 但停止已确认可归还物理额度，仍禁止盲目重试该动作。结果 succeeded 但停止未确认也不能释放物理额度。

未派发且业务记录能持久证明尚未启动的预留，可在取消意图的同一短事务中归还；一旦派发可能已发生，不能用缺少回执或本地计划状态套用此例外，必须由执行端对账。

停止未确认时相关 IP 进入 `quarantine`，仍占全局物理额度。核对无法确认时 `degraded`，仅允许读取平台已有证据及受信管理核对，禁止新的目标请求，包括只读请求。解除时按停止事实、未知结果核对和新动作相关性分别校验，不用 IP 状态改写旧调用。

全局 4 个停止未确认可以阻止新的目标执行，这是容量背压；平台的取消/核对/回收不能因此停止。不得再启动其他 IP 使物理并发超过 4，也不能承诺任何数量 unknown 都不影响目标容量。未知但已停止的调用不应长期占资源，这才是防自锁条件。

公平只对前提满足、授权/预算有效且资源可用的集合评价，采用可校准份额、首触与 aging；不承诺每 Run 同时保底 1 槽，也不保证受阻目标取得研究进展。等待上界的验收固定有界调用、资源恢复假设和可调度集合，预算耗尽或资源永久未知单独报告。

## 8. 前提与复合主张

前提门保存结构、成员、版本、依据与采用成员，成员不得包含授权/预算/租约/取消/旧调用核对等硬约束。提交时拒绝依赖环及超过版本化嵌套深度的结构。门状态与假设状态分开；派发前独立检查硬约束和最新前提。

| 输入 | `all_of` | `any_of` |
| --- | --- | --- |
| T、T | T | T |
| T、F | F | T |
| T、U | U | T |
| F、F | F | F |
| F、U | F | U |
| U、U | U | U |

嵌套同一三值逻辑向上传播。F 只表示当前门不成立，不自动反驳假设。前提退化触发依赖重评，不必构成有效进展，不得反复重置无进展/重试计数。关键反例处理是独立强制维度，不由 any_of 替代。

复合主张另存版本化表达式 `all_of / any_of`、子主张版本引用、作用范围及评估记录，不是把支持/反驳关系混进前提门。复合结构拒绝环和无意义空组。verdict 不是可按大小取 min/max 的全序：先按契约判断命题的 T/F/U，再检查证据与确认等级。析取只要一个有效成员成立可证明整体；全部成员反驳才反驳析取。合取需全部成立，任一成员反驳可在相同条件下反驳合取。

直接证据只能证明“至少一项成立”时可显式绑定整体并按整体契约确认，不能凭此确认任意子项。共享原始证据允许，但每条主张绑定自己的片段、用途和依据；hash 链不必人为拆开，共享材料不算独立来源或独立复现。逻辑蕴含不自动满足复合主张额外的确认等级要求。

子主张或必要依据变化使旧评估不再代表当前输入，强制重算并留版本痕迹；未重算时显示当前未决/失效。有另一有效析取支仍满足整体契约时，新评估可以继续 confirmed，不机械降级。冻结表达式按冻结版本解释，当前重评不修改旧交付。

## 9. 版本、冻结与投影协议

冻结 manifest 是不可变业务输入清单，至少含：标识/Run 及范围版本/冻结时间、契约/判据/有效要求/准入政策版本、主张与评估版本及确认记录、证据/绑定/片段/hash/冻结时完整性及有效期、Review 与 HumanDecision 版本、评分/准入版本、关系/前提门版本、覆盖与冻结分母、主锚点与成本归因版本、自动结束与未决/遗留摘要版本、图修订/筛选范围/快照制品/hash/投影版本/已处理游标、环境与工具引用、`validity_until / retention_until`。

| 字段组 | 锁定的输入内容 |
| --- | --- |
| 身份 | `manifest_id / schema_version / run_id / run_version / scope_version / frozen_at / authoritative_source=versioned_record` |
| 规则 | `contract_versions / criteria_versions / requirement_set_versions / admission_policy_version / completion_rule_version` |
| 主张 | `claim_id / claim_version / evaluation_id / evaluation_version / verdict_at_freeze / lapsed_at_freeze / confirmation_level_met / confirming_review_id` |
| 材料 | evidence ID/采集版本/hash、绑定及具体片段版本、冻结时完整性/可读性、证明用途的有效性规则/时间、保留保护引用 |
| 裁定与准入 | Review、HumanDecision、SeverityAssessment、AdmissionDecision 的 ID/版本及冻结时结果，不猜测自然人身份 |
| 范围与统计 | 覆盖记录/登记来源、分母版本及 total_basis、主锚点版本、成本归因与唯一结算引用、遗留/未决摘要与自动结束记录 |
| 图与环境 | graph revision、projection/schema 版本、筛选范围、快照制品/hash、该快照已处理 Run 游标、环境/工具制品版本与可复现限制 |
| 时效与保存 | `validity_until / retention_until` 及策略版本，字段为空时的明确含义与输入各自失效规则 |

原始证据、业务输入与必要快照制品在承诺保留期内受到相应保护；固定清单本身不保证其所列外部 URL、依赖或未保存制品将来可得。

`validity_until` 规定交付整体的当前适用期，`retention_until` 规定制品保留；任何必要输入更早失效先触发退出。无统一有效期的输入明确其失效规则，不填假日期。manifest 只保存冻结时事实，不实时回写 lapsed 或队列积压；读取时叠加当前可核验状态，界面同时给出 current/frozen 版本。修补形成新 manifest，不修改旧版。

权威源为版本化业务记录，事件用于增量投影和保留期内游标补拉；事件不是唯一重建来源。投影可从业务记录重建，按相同输入版本与水位核对语义，不比较坐标。保留的清单、历史记录与制品决定 as-of 能力；材料缺失须显示不可核验，不承诺可重复执行得到相同结果。

图快照/增量使用 Run、投影版本、快照标识、输入修订与 published/projected 水位。客户端只合并同快照上下文、连续且去重的增量；新事件不是自动使整个快照失效，协议允许在同一投影版本上顺序推进。版本不兼容、历史缺口或跨快照分页返回明确重载要求；历史对象列表用 keyset，证据字节分段读取的 offset 不受此限制。

目标时间、Runner 采集时间、业务发布序与投影读取时间分别保存；默认 Run 发布序排序。跨 Run 各自游标并排，采集时间近似对齐仅用于阅读，标为启发式，不创建绑定或报告证明。查询返回逻辑展开量、结果量、深度/路径量、耗时、截断原因、水位及 `total_basis=exact / estimate / unknown`；只有同一版本完整计数才给 exact，分母未知不显示覆盖百分比。资源控制和物理工作量采样按 ADR-0015/0016。

## 10. Phase 0：映射与兼容策略

这是一组实施前设计步骤，不是另一个 P0 运行阶段。现有源码保存 Run、ResearchTask、AgentSession、Decision、ToolCall、ToolResult、Evidence 和 ReconciliationDecision；没有完整 Claim、Attempt、Finding、Review、准入或 frozen manifest 表。现存核对 `outcome=undetermined` 是“调用是否发生仍未决”，不是 A1 未决主张，禁止按同名迁移。

### 0.1 旧语义映射

下表的旧 Finding 值来自设计文档；只有实际导入了这种记录才执行相应转换，不能从没有数据的旧稿生成已完成评估。

| 旧对象/值 | 新对象与规则 | 不能推造的事实 |
| --- | --- | --- |
| Finding `suspected` | A1 undetermined；已有实际支持时经评估为 supported | 无证据不能 supported |
| Finding `supported` | 核对支持引用与条件后 A1 supported，否则 undetermined 并留迁移问题 | 不补确认/复审 |
| Finding `verified` | 旧证据充分标签先映射要求评估；适用契约与输入可核验且达到等级才 A1 confirmed，否则 supported/undetermined 并列缺口 | 不自动生成人工或独立 Review |
| Finding `inconclusive` | 有支持为 supported，否则 undetermined；认知结果/原因记 inconclusive | 不改为 refuted |
| Finding `refuted` | 有反例、条件与版本且满足判据才 A1 refuted；否则保留旧值为历史、当前未决 | 不把执行失败当反例 |
| 旧 `admitted` | 创建可追溯 A4 历史输入；全部当前门槛满足才 admitted_current | 不由 Attempt 或旧标签推入正式库 |
| 旧 `stale` | 按实际原因拆为有效性到期、不可读/缺失、更正或版本不匹配；相关评估 lapsed | 不用一个词猜失效原因或日期 |
| ToolCall `unknown / incomplete` 与停止 observation | 留在执行记录，分别关联 A3/A6；核对决定保留原语义 | 不迁为 A1 refuted，不释放未确认物理占用 |
| ResearchTask/Run 状态 | 保留原生命周期；按已记录调用和研究边界建立关联 | 不凭最后调用构造 Attempt 确认 |

`dual_read` 是有界的兼容读取：明确新接口以新轴为权威，旧接口只由新记录生成兼容视图；尚未转换的来源走隔离的转换读取路径并显示缺口。保存旧原值/来源版本及映射规则版本，比较两种读取的事实语义并产出漂移清单。不能让两个可写状态同时作权威；若实施确需 dual_write，必须另定事务和单一写入口方案。退出条件为来源盘点完整、无未解释漂移、消费者已迁移、回退读路径验证；未决转换可留存但不参与当前确认。

### 0.2 命名及 0.3–0.5 锁定顺序

`verified` 不全局替换：旧 Finding 证据标签、工具验证结果、能力就绪、机器审阅与人工裁定先逐对象盘点。本规格的新字段分别称 claim confirmed、auto_reviewed、independent_reviewed、human_confirmed；旧人工 outcome 为 confirmed 时必须带 HumanDecision 对象，防歧义。历史 ADR、报告与验证记录保留原名称并标替代关系。

顺序：0.1 来源盘点/映射与兼容读策略 → 0.2 verified 对象/语义映射 → 0.3 六轴及接口字段/引用方向 → 0.4 frozen manifest 完整输入 schema → 0.5 按 §3 锁定默认等级与有效要求版本。本文已固定设计要求；实际列/索引、来源数据盘点、转换作业和回退步骤须随实施补齐，不声称已执行迁移。

## 11. 成对验收与切片

| 规则 | 必须通过 | 必须阻止或保留未决 |
| --- | --- | --- |
| 六轴 | 自动复审与 confirmed 分别可查询，待模型只影响生命周期 | 用已复审代替成立，用模型不可用降级主张 |
| 等级 | auto/independent 主张自主确认；server 实证自动执行、最终待人工 | 把 human 等级变为权限内执行前审批；自动主张直接免人工入库 |
| 判据 | 新方法按适用契约确认，匹配事实可自动确认 | 改名减少要求，无契约送审后绕过判据，版本命中冒充利用 |
| 分类未决 | 分类争议保留证据，独立合法研究继续；结束前评估或登记带原因的未决结束 | 把未决当通过或拒绝，或让它无限挂起自动阶段 |
| 前提与硬约束 | §8 三值表每格及嵌套传播正确，门 F 不自动反驳假设；满足门后仍独立检查执行许可 | all_of 缺必要成员却通过、any_of 只有未知却通过、授权等硬约束进入前提组、依赖环或超深度 |
| 尝试与查重 | 不同参数对照、合法重复命令/复现/瞬态重试按语义保持正确尝试身份；实例重建保留调用链 | F1/F2 直接阻断、普通重建造新实验或抹去旧调用、改尝试绕过未知核对 |
| 反驳 | 反例、条件与版本齐备才能 refuted，可从 confirmed 直接留痕转入 | 失败/缺凭据/受阻等价于证伪 |
| 引用 | A1 指向 Review，A4 指向完整输入版本 | A1/A4 互相依赖 |
| 复合 | A=T、B=U 可使析取 T，B 仍 U；直接整体证明不确认子项 | 强迫每支成立，按 watermark/置信度处理析取 |
| 复合重评 | 一支失效但另一支有效，新评估可保留 confirmed | 静默沿用旧版本，或机械把整体降级 |
| 共享证据 | 不同主张显式绑定同一来源 | 伪装独立复现/多来源 |
| 失效 | 读时即时排除必要输入过期的当前结论；历史保留 | 等 GC 才失效，冻结豁免有效期 |
| 重审 | 过期登记需求与原因，已结束 Run 等待明确处理 | 自动花费预算、重开目标测试，或伪称正在审 |
| 资源 | unknown 且停止确认可释放物理额度，继续核对结果 | 控制槽释放/成功结算/租约过期被当作停止 |
| 容量 | 4 个停止未确认时新目标背压，取消/回收仍可用 | 再启动其他 IP 超过全局物理 4 |
| IP | 跨 Run 同 IP 1，多 IP 调用检查所有实际目标 | 只按导航锚点锁定，degraded 下发起只读请求 |
| 完成 | 提交前新证据参与；受限结束有版本、原因与撤销唤醒记录 | 队列暂空即完成，迟到建议重开结束 Run |
| 冻结 | 时效/保留分开，修订另建版本，缺材料明确标记 | 修改旧清单，回收失去保护的历史仍显示可核验 |
| 同步 | 同版本连续增量、缺口重载，keyset 分页一致 | 乱序跨快照拼接或每事件使全图读取无限失败 |
| 迁移 | 旧值按对象转换，unknown 核对决定保留 | 自动把 verified 变 confirmed/人审、假设不存在的旧表 |

成对指标、固定夹具及容量验证归 [0003 §9](./0003-agent-research.md#9-图语义与调度的成对验收)。字段/版本归 P2-B/D，基础图归 P2-F，资源/容量与两类长时验证归 P2-E；P1 顺序不变。阈值、查询额度、份额、等待 SLA 和有效/保留期限须实测或按契约明确，不以本稿生成验收结论。
