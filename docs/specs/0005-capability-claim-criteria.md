# P2：能力类主张判据

状态：草案（未经评审），未实现；归属 P2-C/D，与 [0004 评分与准入](./0004-finding-admission.md) 协同。日期：2026-10-10。依据：[PROJECT §9.1、§11](../../PROJECT.md)、[ADR-0012](../adr/0012-minimal-proof-and-target-data.md)、[ADR-0013](../adr/0013-severity-and-finding-admission.md)、[ADR-0015](../adr/0015-graph-semantics-and-projection-boundary.md)、[P2 规格](./0003-agent-research.md)。

## 1. 目的与定位

本规格是**能力类主张判据的唯一来源**。ADR-0015 只记录原则（必需维度的三层组合、契约由 `runs` 持有、结论状态与入库分离），Finding 结构（总纲第 11.2 节）与准入规则（[0004](./0004-finding-admission.md)）通过引用关联本规格，不复述具体要求表。

需要区分两类记录：

| 记录 | 含义 | 是否受本规格约束 |
| --- | --- | --- |
| 观察 | 端口与传输可达性、服务与组件识别、版本与公告适用性 | 不作为能力主张；按第 5 节处理 |
| 能力主张 | 声称目标上存在某种能力或边界失效（如可执行代码、可绕过访问控制、可读取不应可见的数据） | 受本规格约束，须满足展开后的有效要求 |

"目标上发现了什么"与"目标上能做到什么"必须分开表达。工具执行完成、扫描命中、文章描述与版本匹配都不构成能力主张的证明。

## 2. 展开后的有效要求

必需维度由三层组合而成，加载时校验**展开后的结果**：

| 层 | 内容 | 约束 |
| --- | --- | --- |
| 通用要求 | 目标归属、来源、证据片段、访问条件、反例处理、结论范围 | 所有能力主张一律适用，不因类型不同而省略 |
| 能力类要求 | 第 4 节各能力类的必需维度 | 按主张所属类别适用，不可由专用类型覆盖或删除 |
| 专用附加要求 | 特定协议、组件或问题类型的附加证据要求 | 只能**增加**要求，不得省略前两层任何必需维度 |

专用契约可以继承公共要求而不重复填写。任何契约若省略通用或能力类必需维度，加载时即被拒绝，不进入可用状态。程序校验要求与引用是否满足；证据语义是否充分仍由独立复审判断，"字段填齐"不等于证明。

完整性与限制随引用传播：任何引用该主张证据的图节点、Finding 与报告，都必须同时可见片段完整或截断、调用结果完整、尝试是否结束、实例停止与回收是否确认这四项。

## 3. 结论状态与上限

沿用既有证据状态 `suspected / supported / verified / inconclusive / refuted`，并固定以下边界：

- `verified` 要求展开后的有效要求全部满足，且证据语义经独立复审确认；不以破坏性效果为条件。
- 未登记类型、或有效契约无法覆盖必要判断时，结论停留在 `supported`，并显示**验证要求未明确**。`尚无专用类型`、`证据不足`、`无法判定` 是三个不同状态，不得合并显示。
- 缺少必需对照、缺少关键证据或存在未处理反例时，结论上限为 `supported`，不得进入 `verified` 或正式漏洞库。
- 无法判断与"已排除"是不同结论。目标不可达、工具超时、畸形输出或访问条件缺失时，不输出"已排除该问题"（总纲第 14.1 节）。
- 主张成立与入库资格分两层，入库条件见 [0004](./0004-finding-admission.md)。

## 4. 能力类判据

以下每类明确适用条件、必需维度、最低证明要求、对照规则、不适用判定、反例处理与无法判断时的状态。除 C1 的最低留证要求引用既有基线外，各类判据均为**新增设计**，未经实现与验收。

### C1 执行能力

来源：最低留证要求引用总纲第 9.1.1 节（既有基线）；其余为新增设计。

| 项目 | 要求 |
| --- | --- |
| 适用条件 | 声称在目标上获得命令、代码或脚本执行能力，包括直接执行、经注入达成执行、经反序列化或模板表达式达成执行 |
| 必需维度 | 目标绑定（实际连接 IP、端口、Host/SNI，适用时）、执行身份、所在执行环境、时间、完整命令与输出、退出与收尾确认 |
| 最低证明要求 | 按总纲第 9.1.1 节执行最少的只读身份、主机与时间留证，取得后立即退出该验证分支；不继续读取业务内容或凭据、不提权、不驻留、不横向 |
| 对照规则 | 默认不适用：以已授权的执行路径或已具备的访问条件取得留证时不需要对照。主张依赖"由某个输入导致执行"时，须保留该输入的观察与一次成功触发的完整证据，可复用同一份证据，不强制第二次执行 |
| 不适用判定 | 仅当主张不依赖输入可控性时成立；由复审按契约确认并留记录，模型不得单方豁免 |
| 反例处理 | 需排除把工具自述、包装脚本输出或预期现象当作执行证据；身份或执行环境无法核实时标注歧义，不补做横向探测 |
| 无法判断时 | 停留在 `supported` 并显示具体缺口（如执行环境不可确认、目标时钟可疑、身份受限条件不明） |

### C2 访问控制失效与认证问题

来源：新增设计。

| 项目 | 要求 |
| --- | --- |
| 适用条件 | 声称可访问本不应访问的对象、可绕过认证或授权检查、可越权操作（含越权读取） |
| 必需维度 | 主体与凭据引用（或匿名）、对象与入口、动作、前后状态、受影响范围、是否触及业务数据 |
| 最低证明要求 | 存在可比较的对照状态（同一动作在有权限与无权限条件下，或合法主体与非法主体之间）且可观察差异稳定；只读取证明所需的最小范围，必要时仅记录对象存在与类型，不导出业务数据 |
| 对照规则 | 必需。对照不可构造或缺失时结论上限为 `supported`，并显示"缺少对照" |
| 不适用判定 | 契约不允许以"资源本就公开"为由豁免；若资源确属公开，须先证明其公开性，结论按观察处理 |
| 反例处理 | 需排除缓存、偶发状态、公开资源、重定向或前端展示造成的假象；同一路径的匿名可访问性须核实 |
| 无法判断时 | `supported`，并标注缺失的对照或不可访问的状态 |

### C3 信息泄露与敏感数据暴露

来源：新增设计。

| 项目 | 要求 |
| --- | --- |
| 适用条件 | 声称可通过某入口读取本不应可见的信息，如配置、日志、源码、元数据、凭据引用或内部标识 |
| 必需维度 | 具体片段或脱敏片段、位置与入口、访问条件、范围界定、敏感度依据 |
| 最低证明要求 | 直接观察到的最小片段即可支持主张；不得为证明而导出业务数据、遍历记录或扩大读取范围；片段超出最小必要时截断并标注 |
| 对照规则 | 默认不适用；但须核查该信息是否本属公开或已由目标主动提供 |
| 不适用判定 | 由复审确认"信息本属公开/示例数据"并改变分类或结论，而非仅豁免对照 |
| 反例处理 | 示例数据、占位内容、前端内嵌的公开配置不得计为泄露；脱敏副本不得替代原始证据引用 |
| 无法判断时 | `supported`，标注"范围未界定"或"敏感度依据不足" |

### C4 注入与解释面操纵

来源：新增设计。本类适用于**未达到代码或命令执行后果**的注入与解释面问题。

| 项目 | 要求 |
| --- | --- |
| 适用条件 | 服务端注入（SQL/NoSQL/LDAP/XPath/模板表达式等）或客户端注入（存储型/反射型脚本注入）造成的未授权读取、逻辑绕过或客户端执行 |
| 必需维度 | 参数位置与入口、输入语义、对照请求、可观察差异、重复次数与基线噪声、数据影响范围；客户端注入另需受控执行环境的上下文证据 |
| 最低证明要求 | 差异可由对照与有限重复确认（回显、布尔、时间或等价可观察信号），且未使用破坏性载荷、未导出数据；不得向真实用户投递载荷 |
| 对照规则 | 必需；时间型或统计型判定须记录基线噪声与重复次数 |
| 不适用判定 | 不允许豁免；无法构造对照时停留 `supported` |
| 反例处理 | 需排除参数无关的偶发现象、WAF/代理造成的伪造差异、缓存与字符编码造成的误判 |
| 无法判断时 | `supported`，标注判定手段的局限（如仅时间差异、无回显） |
| 归并规则 | 若取得执行后果，主张归入 C1，按 C1 的留证要求处理 |

### C5 组件与条件适用性

来源：新增设计。

| 项目 | 要求 |
| --- | --- |
| 适用条件 | 声称某组件、版本或配置条件下的缺陷在本目标上可利用 |
| 必需维度 | 组件与版本（或功能特征）观察、适用条件核查、触发或受限结论 |
| 最低证明要求 | 版本命中本身不构成证明；须有本目标的适用性观察，并取得触发证据；无法触发时不得声称可利用，结论按观察或 `supported` 处理，可标注上游严重性作为来源引用 |
| 对照规则 | 按所产生的后果类型适用 C1–C4 的对照要求 |
| 不适用判定 | 不允许以"版本匹配公告"豁免实际触发要求 |
| 反例处理 | 补丁已应用、功能被禁用、前置条件不成立都构成反例；须保留证据 |
| 无法判断时 | `supported`，标注"前提未验证"或"仅上游命中" |
| 归并规则 | 后果归入 C1–C4 相应类别判定，不单独形成执行能力结论 |

### C6 配置与加固缺陷

来源：新增设计。

| 项目 | 要求 |
| --- | --- |
| 适用条件 | 声称存在弱配置、明文传输、暴露的管理接口、缺失校验或类似加固问题 |
| 必需维度 | 配置事实、影响路径、受影响范围、观察与推导的区分 |
| 最低证明要求 | 直接观察到的配置事实；影响可由已证事实合理推导并标明推导部分。缺少实质安全影响时不满足入库条件（总纲第 11.4 节） |
| 对照规则 | 默认不适用；涉及访问能力时按 C2 处理 |
| 不适用判定 | 由复审核查"是否存在实质影响"并改变分类或结论，不豁免影响判断 |
| 反例处理 | 组件旧、版本号暴露、缺少某个头部、仅公开正常信息本身不构成影响 |
| 无法判断时 | `supported` 或按信息记录处理，标注影响未证明 |

## 5. 非能力类观察

下列记录按 Observation 与 SourceArtifact 处理，不作为能力主张，不使用第 3 节的 `verified` 语义：

| 记录 | 处理 |
| --- | --- |
| 端口与传输可达性 | 由程序按执行事实判定，记录不可达、超时、拒绝连接与未知状态；不把探测失败等同于主机不存在（总纲第 4.2 节） |
| 服务与组件识别 | 带来源、置信度与证据引用；指纹歧义作为待验证项，不推定组件与版本 |
| 版本与公告适用性 | 保留为线索与来源引用，可促成适用性研究；不进入正式漏洞库，不作为本目标评级（[0004](./0004-finding-admission.md) 第 3 节） |

## 6. 对照的适用与不适用通则

- 对照要求按主张类型适用，不机械要求每项主张都执行额外对照动作；对照可以由同一次采集中的既有观察满足。
- 不得为满足形式而增加目标动作。优先只读或最少新增数据的验证；确需新增时按总纲第 9.1.2 节登记必要性、位置、预计数量与上限。
- 不适用必须符合本规格的适用条件，并由复审确认、留下记录与依据；**不能仅凭模型填写理由即豁免**。程序校验不适用声明的类别、引用与版本是否齐备。
- 对照本身也是证据，需有归属、来源、时间与完整性限制；对照缺失或不可比时结论上限为 `supported`。

## 7. 版本、职责与校验

- `runs` 持有判据表与结论状态；`harness` 只提出建议；投影只读读取结果。判据配置入版本控制，逻辑上属业务判定规则，与执行环境 profile 分开；Agent 不可修改。
- 每次评估固定契约版本与输入版本（主张、证据集合、评分、复审、人工决定各自的版本）。主张类型、必要条件或证据变化后必须重新评估，旧复审不得直接沿用。
- 修改判据本身属于产品决定：需要有明确版本迁移与评审，不能在提示词中降低阈值，也不能因某次评分或准入需要而放宽（与 [0004](./0004-finding-admission.md) 一致）。
- 分类不能只接受 Worker 标签：主张描述、所声称能力、证据与类型适用性一并进入独立复审；分类争议保留未决。分类未决不冻结独立的合法研究，但依赖该未决分类才能判断可行性的后续动作须等待。

## 8. 验收案例

| 场景 | 必须得到的结果 |
| --- | --- |
| 新方法在既有能力类覆盖下完成最小实证 | 允许进入 `verified`，不因"无专用类型"被拒 |
| 把 C1 主张改标为未登记类型以省略必需维度 | 停留 `supported` 并显示验证要求未明确；不得进入 `verified` 或正式库 |
| 契约省略通用或能力类必需维度 | 加载时被拒绝，不进入可用状态 |
| 访问控制主张缺少对照 | 停留 `supported` 并显示"缺少对照"；不进入正式库 |
| 声明"对照不适用"但无契约依据或记录 | 拒绝豁免；按缺少对照处理 |
| 组件版本命中而无可利用证据 | 作为观察或待验证线索；不声称可利用、不入库 |
| 注入取得执行后果 | 归入 C1 并按第 9.1.1 节留证后退出，不按 C4 处理 |
| 目标不可达或工具超时 | 标注不可判断；不得输出"已排除该问题" |
| 缺少认证条件 | 记录阻断条件并保留研究分支；不进行凭据猜测或资源耗尽的尝试 |
| 禁止类别动作（DoS、破坏删改、驻留、隐蔽规避、凭据窃取、无范围横向移动） | 拒绝执行；不因评分或准入需要而开放 |
| 分类存在争议 | 保留未决；依赖该分类的后续动作等待，独立分支继续 |
| 判据版本变化后沿用旧评估 | 拒绝写入，要求按新版本重评；历史结果保留 |

## 9. 待评审事项

本规格为草案。开工前需评审并按 [P2 规格](./0003-agent-research.md) 分片实施。评审时应确认：各能力类的必需维度是否完整且可程序校验、对照与不适用规则是否会诱发无价值的目标动作、C4 与 C5 的归并边界是否清晰、以及判据表首版条目与版本迁移方式。实现前不产生任何验收结论。
