# P2：漏洞严重性评分与正式漏洞库准入

状态：设计已确认，待实施、未验收。日期：2026-10-10。归属 P2-D，依据 [PROJECT §11](../../PROJECT.md)、[P2 研究规格](./0003-agent-research.md)、[ADR-0013](../adr/0013-severity-and-finding-admission.md) 与 [ADR-0017](../adr/0017-claim-confirmation-and-frozen-delivery.md)。状态、当前有效性、冻结与迁移按 [0006](./0006-state-model-and-delivery.md)，能力判据按 [0005](./0005-capability-claim-criteria.md)。

## 1. 目的与选择

正式漏洞库只保留有实质安全影响、证据充分并经人工确认的发现。无害信息、低危问题和未证实线索不混入最终漏洞数量，但研究记录、排除原因和必要遗留披露继续保存。

采用 **CVSS v4.0 技术严重性评分 + HuntWeave 入库策略 v1**。不引入 SRC 归属、赏金、提交价值或任意模型加权总分。CVSS 提供可复算的严重性表达，不能单独证明目标确实存在漏洞，也不是目标组织的完整业务风险或收益评分。[FIRST CVSS v4.0 规范](https://www.first.org/cvss/v4.0/specification-document)

准入按**机器初审筛选 → 人工确认**组织：机器复审筛出候选并给出证据、向量与理由，人工确认才使发现进入正式库。筛选与准入规则由本项目独立定义并保留逐条依据，不采用外部资产测绘、SRC 归属或扩大危害的流程。

## 2. 评分契约

默认计算 `CVSS-B`；若有可靠的目标环境修正依据，另保存 `CVSS-BE`，作为本条发现的有效严重性评分。两者明确命名并保留向量；不能把环境修正偷偷写进基础指标。采用 BE 的条目不能因为环境事实暂时缺失就自动退回更高 B 分入库，应标为待重评。首版不强制使用 Threat/EPSS 或完整资产价值体系。

分数由固定版本的标准算法计算，模型只建议结构化指标与依据；UI、API 和导出同时给出分数、完整向量、类型、评估版本和理由，不接收模型自由生成的数字作为正式分数。CVSS 的名称、分组、向量和等级按 FIRST 规范处理；CVSS 由 FIRST 拥有并按其许可使用，发布评分时同时提供向量与归属说明。[FIRST 规范与使用条件](https://www.first.org/cvss/v4.0/specification-document)

| 有效严重性分数 | 等级 | 本项目默认处置 |
| --- | --- | --- |
| 0.0 | 无技术危害 | 信息记录，不入正式漏洞库 |
| 0.1–3.9 | 低危 | 低危记录，不入正式漏洞库 |
| 4.0–6.9 | 中危 | 满足全部准入条件后入库 |
| 7.0–8.9 | 高危 | 满足全部准入条件后入库 |
| 9.0–10.0 | 严重 | 满足全部准入条件后入库 |
| 未能评估（null） | 待评估 | 保留候选，不能当作 0 分或无害 |

等级区间采用 CVSS v4.0；**≥4.0 才有入库资格是 HuntWeave 的产品策略**，不是 CVSS 强制要求。[FIRST 等级定义](https://www.first.org/cvss/v4.0/specification-document#qualitative-severity-rating-scale)

每项评分保存：Finding/证据/环境输入版本、评估者、时间、算法/计算器版本、Base/Environmental 指标与逐项证据或推导依据、完整向量、分数/类型、缺失事实、评估状态。主张判定、复审、人工决定与准入按 0006 的独立维度保存，不另造可与之矛盾的置信度百分比。

影响指标可以由最小实证及明确适用的技术事实合理推导，须区分直接观察与推导。RCE 仅执行身份/主机/时间命令也能证明相应执行能力；不必真的删数据、读取凭据或中断业务以证明潜在影响。推导上限受实际身份、隔离和条件约束，容器内命令执行不直接等同于宿主控制，更不等同于整个组织失陷。

必要指标没有依据时不补猜、不中和成“无影响”；评估标为待补充。外部 CVE/扫描器分数只保留为来源引用，不能替代本目标的适用性与证据核查。版本匹配但利用条件未知的线索可以标注上游高危，仍不得把该数值当成本项目已确认评分。

## 3. 入库必须同时成立的条件

`runs` 以同一输入版本重新检查以下条件，生成可追溯的准入结果：

1. **实质安全影响**：存在具体的安全边界失效、未授权能力或有意义的信息/完整性/可用性影响，列出受影响主体、对象、条件与证据。组件旧、版本号暴露、缺少某个头部或仅公开正常信息，本身不满足此项。
2. **本轮证据充分且主张当前成立**：Finding 的必要主张按适用有效契约达到 `confirmed`，未 lapsed；关键证据可读且适用、目标归属准确、前提成立，反例已处理。仅有文章、版本/CVE 命中、模型断言或无效历史引用不能满足。旧 verified 标签不自动满足本项，映射见 0006 §10。
3. **有效评分达到中危**：正式评估完成且有效分数 ≥4.0；评分未过期。高分不能补偿证据不足，低危即使证据充分也不入库。
4. **独立复审与人工确认**：当前 Review 为 `recommend_confirm`，人工为 `confirmed`，均基于相同的当前主张、证据与评分版本。未完成 AI 复审的发现可交人工处理，但在本策略下尚不能成为正式入库条目，不能补造机器结论。
5. **有效且非重复**：无尚未处理的关键反例、主张撤回、版本冲突或重复归并；同一根因/入口/参数按领域去重保留一个有效条目，多轮证据追加关联。

必要的独立复审可以是原始证据审阅或有界复现，必须标明 `existing_evidence` / `fresh_replay`，不要求每一项都重复目标动作。confirmed 不以破坏性效果为条件，证据充分性按 [0005](./0005-capability-claim-criteria.md) 判断。主张确认等级为 auto/independent 也不能省略本节要求的独立推荐与人工确认。用户明确禁止的破坏/删改行为不会因为评分或准入需要而开放。

准入结果保存 Finding、必要主张及评估、证据集合/绑定、评分、复审、人工决定、契约/判据及准入政策的完整版本，结果、原因与时间；状态与失效原因见 [0006 §6](./0006-state-model-and-delivery.md#6-准入与当前有效性)。门槛/规则初始固定为 `finding-admission-v1`，首版不提供把低危拖入正式漏洞库的开关；改变准入政策需明确产品决策与版本迁移，不能只在模型提示词中降低阈值。

## 4. 记录去向与用户体验

| 记录 | 去向 | 展示要求 |
| --- | --- | --- |
| 无害/低危且结论明确 | 信息与低危记录 | 默认不计入漏洞库和正式漏洞数量，可回查依据 |
| 疑似高影响但证据/评分/复审未完成 | 待验证或待复审 | 标明具体缺口；不因未入库就显示无害 |
| 中危及以上、机器推荐、待人工确认 | 人工复审队列 | 先展示主张、最小证据、评分向量/依据与反例 |
| 全部准入条件成立 | 正式漏洞库 | 显示有效评级、证据、条件、版本与确认记录 |
| 已反驳、撤回或重复 | 历史/归并记录 | 原证据与原因仍可追溯，不物理删除审计链 |

最终报告的正式漏洞章节与计数只使用准入后的条目；自动阶段结束但尚待人工确认时显示“待复审候选”，不能宣称已入库。低危/信息性结果默认只给数量与可选附录，避免淹没重点。没有条目时写“无符合入库条件的已确认漏洞”，不能写“目标安全”；同时展示未决高影响候选、覆盖缺口与限制。

测试新增数据、脏数据、异常副作用、执行失败和覆盖限制不受漏洞分数过滤。即使唯一发现被判低危，遗留清单也必须出现在 Run 摘要和报告中；禁止把数据污染藏进折叠的低危附录。

## 5. 版本、职责与恢复

漏洞库是现有 Finding 加评分/复审/人工决定的受控查询视图，不建立复制证据与状态的第二套库或部署服务。`runs` 独占评分/准入写入和去重，harness 提出可解释的评估，evidence 提供只读原始证据，timeline 发布变化。

Worker 可建议影响与指标，Reviewer 独立核查，程序计算并校验向量，人工确认本条版本。人工调级须修改有依据的指标/影响判断并重算，不能只把数字从 3.9 改成 4.0；新的指标或影响主张需重新完成复审，不用旧 Review 越过门槛。

必要输入失效、关键反例未决、环境变化、主张更正或规则失效使当前准入立即退出，登记待重审且不计入当前有效漏洞集合；读取时计算有效性，不依赖 GC 或人审是否已处理。冗余辅助材料变化按影响重评，不机械失效全部结论。历史入库、人工决定与冻结清单保留；保存保护不豁免有效期。证据过期/缺失显示不可核验，未来补证须重新确认输入；重审不能自行重开已结束 Run 或绕过预算。历史报告不自动改写，冻结行为见 0006 §9。

评分、准入与报告采用短事务和输入版本检查，冲突返回 `version_conflict`；重放同一评估不重复创建入库记录或重复结算模型费用。报告输入增加评分与准入版本，旧报告不能覆盖新等级或新增遗留清单。算分属于确定性逻辑，无须每次展示再请求模型。

准入过滤不会删除研究事实，也不能变成研究前的永久忽略清单。版本线索可以促成适用性研究；低危线索如果在授权内构成有证据的高影响链，可以形成新的关联主张再评估，不能靠相加多个低分提升等级。研究优先级可参考预期价值和预算，但高分不会授予更大权限。

## 6. 验收案例

| 场景 | 必须得到的结果 |
| --- | --- |
| 只发现组件旧版本/版本号，即使公告分数 9.8 | 作为观察或待验证线索；不入库、不伪造本目标评级 |
| 版本问题进一步获得适用性及最小实证，满足中危以上与复审条件 | 允许入库，不能因“版本问题”关键词一刀切排除 |
| 无害公开信息或已确认 0–3.9 分问题 | 不进入最终漏洞库/正式计数，研究历史可查 |
| 4.0 / 7.0 / 9.0 边界与相邻分数 | 标准等级正确；4.0 仅获得准入资格，其余门槛照常检查 |
| 分数高但关键证据缺失；未知指标；机器或人工未确认 | 保持候选并显示各自原因，不按 0 分或低危处理 |
| RCE 最小只读证据，未真正读取敏感数据或制造损害 | 根据已证能力与受限条件评估；不要求破坏性补证，不机械标 10 分 |
| 评分中来了反例/人工改级，或环境修正依据失效 | 拒绝旧版本写入，重新评估；历史保留，不静默退回更高基础分 |
| 同一根因多工具命中、多个低分线索组合 | 去重归并；组合须有独立证据主张，不能加总分数入库 |
| 低危过滤、无漏洞、失败或取消但产生脏数据 | 遗留清单仍醒目披露，不自动删除/修改目标记录 |
| 入库后证据过期/撤回，服务重启或事件重发 | 当前可核验状态更新、历史保留；重放不重复入库 |

评分实现使用锁定版本的计算器，并与 FIRST 官方算法/已知向量结果核对；不让 LLM 口算公式。准入使用固定证据验证版本/事务与边界，无须连接真实外部目标。评价误入库率、漏收有实质影响发现的比例、人工复审负担和评分一致性，不把过滤数量或最终漏洞数作为优化奖励。
