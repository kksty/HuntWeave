# P0：工程骨架与运行契约

状态：部分实施，P0-A 三服务工程启动已验证，其余切片待实现。日期：2026-10-08。依据：[PROJECT.md](../../PROJECT.md)、[开发约定](../../AGENTS.md)。当前成果与限制见 [启动验证记录](../validation/0001-startup.md)；下文完整闭环仍属于验收要求。

## 1. 交付目标与范围

交付一条可演示路径：配置全局密钥 → 登录 → 创建项目并粘贴 IP/授权 → 启动假 Run → 查看 Agent/调用/证据时间线 → 暂停、取消或重启 → 从持久状态继续 → 人工结束演示。

同时在自建隔离靶场完成 Runner 网络/进程回收技术验证，给 P1 提供受支持宿主 profile。P0 产品模式只运行固定假动作，不执行用户 Shell、真实扫描、公开 PoC 或外部目标连接。界面始终标为“开发演示 / 假执行”；假输出不能形成真实漏洞结论。

P0 不实现动态安装/工具保留、真实模型/联网研究、完整 Finding/Reviewer 报告、定时调度或所有规划资源接口。这些仍属于后续首版阶段，不提前生成空菜单或空表。GitHub 上的项目代码与开发授权不构成对外部目标的测试授权。

## 2. 固定实施选择

- 当前开发与首个受支持部署 profile 为 Windows 11 工作区 + Docker Desktop WSL2 后端，源码直接位于 Windows 文件系统。Docker Desktop 自己的 `docker-desktop` WSL 发行版承载 Linux 容器运行时；单独安装的 Kali WSL 发行版不属于项目依赖、运行时或隔离边界。Linux 宿主暂不纳入本轮部署承诺，未来通过新的宿主 profile 和独立验证加入。
- 一个 Compose 项目，app/postgres/runner 三个常驻服务。app 的 API 与 agentd 是独立受监控进程；Runner 通过认证的内部接口工作，只有 Web 入口发布端口。
- PostgreSQL 分开保存业务 schema 与 LangGraph checkpoint schema；迁移职责分开，在启动接收任务前完成。首版只有一个活动调度进程，内部可并发处理会话。
- 真实 LangGraph + 确定性模型 Adapter + 假执行 Adapter。根据不同假输出产生不同下一步，保留 Collector/Worker/Reviewer 角色和独立上下文；不发起供应商模型请求。
- 六个 Module 及其 Interface 遵循总纲第 7 节。fake 与真实执行端共享提交/查询/取消契约，测试不能绕过预算、策略或 outbox 直接改任务状态。
- 假 Runner 仍具备持久调用账本、事件与重启恢复，不能仅用进程内字典假装支持恢复。演示 profile 不需要 Docker socket；隔离靶场技术验证使用单独明确的测试配置，不把管理权限默认赋给假执行。
- Python/前端依赖、PostgreSQL 主版本与镜像 digest 在实施开始时选兼容版本并提交锁文件；不在规格里虚构尚未验证的精确版本。

## 3. 最小数据与契约

只落支撑闭环的 Project、AuthorizationScope、Run、ResearchTask、AgentSession、Decision、ToolCall、ToolResult、Evidence、AuditEvent、InterruptionRecord、WebSession，以及预算预留、outbox 和事件游标记录。其他实体按后续切片引入。P0 不存真实目标凭据。

### 3.1 创建与控制

目标预览遵循总纲的纯 IP 输入契约；错误行明确定位，不能静默丢弃。Run 固定 IP/端口、授权时间窗、操作模式、预算、profile 和配置版本。默认端口清单作为受版本管理的配置提交并展开给用户，不能把 profile 名称当作具体端口授权。

创建 Run 使用 `Idempotency-Key`：同键同请求返回同一 Run，同键不同规范化请求 hash 返回 409。暂停、恢复、取消、关闭用状态版本检查避免重复/过期页面覆盖。Run 的 phase/status、任务和 ToolCall 的状态枚举以总纲第 8.2 节为准。

`resume` 返回或使用恢复预览：上次完成步骤、待核对调用、剩余预算、当前授权有效性、预计恢复动作。结果未知且未核对时不可从普通恢复按钮重新派发。暂停等当前受限动作收尾；取消需等待执行端确认回收。关闭仅用于没有活动/未知调用的 awaiting_human 阶段，记录人工决定“结束演示”。

### 3.2 运行与执行

工具动作至少传递协议版本、call_id、run/session/decision ID、规范化参数 hash、scope/policy 版本、租约代次、授权与预算引用、执行环境 profile、绝对期限和控制租约到期时间。控制租约默认最长 15 秒、每 5 秒续约，与调用超时分别校验。执行端支持查询能力、提交、查询、取消和续约；准备环境契约可定义但未实现时明确返回未支持。

假执行端只接受固定测试动作 ID 和严格参数，例如受限延时、分块固定文本、预置成功/失败结果；不解释用户提供的 Shell 字符串。相同 call_id/hash 重发返回已有记录，hash 不同拒绝；过期票据、旧租约、错误作用域和未认证请求拒绝。

一轮动作顺序：

1. 领取任务并写租约；读取业务状态和检查点，先核对已有调用。
2. 模型 Adapter 返回结构化 Decision，持久化稳定 decision_id 与会话状态版本。
3. runs 在同一短事务中校验范围/预算，创建 ToolCall、预算预留、outbox 和关键事件。
4. 派发者提交到 Runner；Runner 耐久记录接受意图后回执，启动前再次校验期限/租约与执行约束。
5. Runner 归档输出与证据、记录结果并可重复回传；runs 在一个事务中幂等结算、更新状态和追加完成事件。
6. harness 更新引用业务记录的检查点，继续或等待。检查点失败后重放不能再创建同一动作。

任何网络/模型/工具调用都不能占着数据库事务。预算、主机锁与执行租约的释放依赖真实收尾确认，超时未知不等同于可以再启动一个调用。

### 3.3 时间线与证据

事件使用每 Run 的提交顺序游标；追加时短事务锁定该游标记录。并发提交、重复来源事件与迟到事件遵循总纲第 12.1 节。SSE 的事件 ID 是可补拉游标，断线不改变任务状态；过期游标返回明确缺口与当前快照。

Runner 写入完整输出文件/证据，app 只读归档。先完成文件归档与 hash，再标记证据可用；文件缺失、截断、脱敏、存储满如实展示。控制台展示实际调用参数、状态、耗时、日志偏移、退出码、来源和心跳；假结果有明确标签。

## 4. 第一批页面与接口

| 页面/用途 | 最小接口 |
| --- | --- |
| 登录与会话 | `POST /auth/login`、`POST /auth/logout`、`GET /auth/session` |
| 项目与输入预览 | `/api/v1/projects`、`POST /api/v1/targets/preview`、`/api/v1/scopes` |
| Run 配置与状态 | `POST /api/v1/runs`、`GET /api/v1/runs/{id}` |
| 控制与恢复 | `POST /api/v1/runs/{id}/pause`、`/resume`、`/cancel`、`/close`，`GET /api/v1/runs/{id}/resume-preview` |
| 玻璃鱼缸 | `GET /api/v1/runs/{id}/events`（SSE）、`/event-history`（分页）与任务状态快照 |
| 输出与证据 | `GET /api/v1/evidence/{id}`，按权限提供元数据/分段内容 |
| 环境状态 | `GET /api/v1/system/capabilities`，展示演示能力与真实执行未就绪原因 |

表中缩写路径延续该行的 Run 前缀。只实现上述实际用到的资源方法；API Schema 来自受版本管理的 contracts。版本冲突统一 409，未认证 401；权限/环境阻断有明确 reason_code。POST 等变更入口校验会话、CSRF 与 Origin；前端路由守卫不能代替这些检查。

登录资源与最小存活检查之外，主页/业务静态资源、API、事件、证据与 API 文档统一鉴权。密钥不进入前端构建、URL、日志或 Agent；会话撤销、到期、轮换与已建立 SSE 的失效时限按总纲第 9.3 节实现。localhost 开发 Cookie 与 HTTPS 生产配置分开。

## 6. 故障矩阵

| 注入点 | 验收结果 |
| --- | --- |
| ToolCall 事务前/后崩溃 | 事务前无派发；事务后由 outbox 恢复，预算只预留一次 |
| Runner 接受调用但回执丢失 | 重发同 ID 查到既有调用，固定测试副作用计数为一次 |
| Runner 在启动附近重启 | 根据账本和执行身份核对；无法确认时 unknown，不二次启动 |
| 结果已提交但检查点失败 | 图重跑复用现有 Decision/ToolCall/结果，预算不重复结算 |
| 租约到期但旧调用仍在运行 | 拒绝旧代次新增执行，核对并回收旧调用后才释放主机锁 |
| 暂停/取消与工具完成并发 | 状态版本和确认结果收敛；前端不提前假报取消成功 |
| PostgreSQL 或控制接口暂时不可用 | 停止领取/新派发与续约；执行端最迟在控制租约到期触发停止、有界保存记录，恢复后对账 |
| 归档/事件存储满或文件丢失 | 显示证据不完整/存储阻断，不能仍标记证据可用并继续确认 |
| 两个事务提交顺序不同、来源事件重发 | SSE 不漏事件、不重复结算，最终与分页历史一致 |
| 登录退出/轮换、SSE 断线/过期游标 | 撤销时限符合契约；重连去重，缺口清晰，无未认证内容泄露 |

pytest 覆盖业务 Interface，PostgreSQL 集成验证锁/租约/事务，Playwright 覆盖登录→演示→控制→恢复路径。取消的真实子进程回收另在隔离靶场验证。测试根据上述可观察行为设计，不为私有辅助函数逐一镜像实现。
