# P2：证据驱动的自主研究与版本化结论

状态：自主研究整体实施草案，未实现、未验收；本轮状态/判据/UI 的设计已确认，行为分别以 0004–0007 为准。日期：2026-10-10。依据：[PROJECT](../../PROJECT.md)、[ADR-0009](../adr/0009-adaptive-research-and-continuous-execution.md)、[ADR-0011](../adr/0011-planning-authority-and-evidence-revisions.md)、[ADR-0015](../adr/0015-graph-semantics-and-projection-boundary.md)、[ADR-0016](../adr/0016-scheduling-and-resource-policy.md)、[ADR-0017](../adr/0017-claim-confirmation-and-frozen-delivery.md)；[0005 判据](./0005-capability-claim-criteria.md)、[0004 准入](./0004-finding-admission.md)、[0006 状态/交付/迁移](./0006-state-model-and-delivery.md)、[0007 UI](./0007-research-workbench-ui.md)。P1 的真实隔离、取消、未知调用核对和证据链通过验收后，才接到真实执行；可提前用固定证据验证领域契约。

## 1. 目标与职责

一次发布 Run 后，系统能依据工具返回选择研究方法，处理串行前提和并行分支，自主准备所需工具，完成 AI 复审后停止自动执行，交人工复审。任务数量、图节点数、运行时长、模型自述和扫描命中数均不是成功标准。

沿用六个 Module，不新增 Planner、黑板、报告或审批部署服务：

| 责任 | 唯一归属 | 调用方可以做什么 |
| --- | --- | --- |
| 研究判断与计划建议 | harness | Collector 提出初始建议；Worker/Reviewer 提出新任务、缺口或停止建议；规划步骤汇总跨任务建议 |
| 任务、依赖、授权、预算、租约、完成判定 | runs | 通过同一 Interface 提交建议、领取任务或申请动作，不能直接改表 |
| 外部执行与停止事实 | execution / Runner | 按 call_id 提交、查询、取消和对账，不能用任务状态推断进程状态 |
| 原始证据内容、完整性、生命周期 | evidence，Runner 独占归档写入口 | 模型只读引用；业务侧管理引用，不改原始字节 |
| Finding、证据绑定、Review、HumanDecision、报告版本 | runs | 接收带版本的候选、绑定和结论；导出从 evidence 读取内容 |
| 事实事件和用户视图 | timeline | 投影可重建，不成为第二份可写研究状态 |

`runs` 是计划的唯一提交者。harness 内规划步骤负责跨任务的模型判断；确定性的发现任务、已满足依赖的释放和限额内补证可以按已批准规则通过相同入口提交，不强制再问一次模型。Worker 在任务目标、授权和预算内自主选工具、写脚本、查资料、修正假设，不等待中央 Planner 批准每一步。

## 2. 事件触发与规划提交

### 2.1 触发条件

有效触发包括关键观察或反例、访问条件变更、任务完成/阻断、Reviewer 补证要求、明确人工输入和到期重试。心跳、stdout 块、token 流、界面刷新、普通摘要重写不触发规划。观察候选先校验来源、绑定和结构，任意输出文本不得直接触发受信命令。

事实/任务变化与规划待处理标记、关联事件在一个业务事务内提交；触发记录保留唯一来源与对应事实版本。通知仅作加速信号。agentd 在启动时以及低频补查时从持久记录查找未处理触发、过期规划租约和到期等待；通知丢失不丢工作，空闲补查不请求模型。

同一 Run 的事件合并使用防抖窗口与最大等待时间，连续新事件不能无限推迟规划。取消、撤销和租约到期由控制路径立即处理，不等待防抖或 LLM。Planner、Worker、Reviewer 使用独立且有上限的并发槽；一个慢模型请求不能阻断租约续约、取消或其他 Run。单个 agentd 可以管理这些槽，不由此引入多机调度。

### 2.2 三段协议

1. **准备**：短事务领取本 Run 的规划尝试，固定 `planning_attempt_id`、代次、输入快照及已读取触发水位，预留模型额度后提交。同一 Run 最多一个有效尝试；不同 Run 可在全局并发内推进。
2. **判断**：在事务外由 harness 构建新上下文并调用模型。上下文含未决任务、相关事实/反例、授权和预算摘要、活动/unknown 调用、依赖产物与证据引用；不靠上一轮聊天记忆维持计划。
3. **应用**：短事务检查尝试代次、相关事实/任务/授权版本和输入前提，校验去重、依赖环、目标、额度与状态。有效建议原子提交任务/依赖、消费水位与事件；旧建议返回 `version_conflict`，不套用新版本静默重发。记录模型实际开销，包括被拒绝的陈旧输出。

开始规划后到来的事件仍保留为待处理；一次提交只能消费其实际读取并有效处理的水位。已提交尝试重放返回原结果；崩溃前已保存的有效模型结果优先复用，业务侧不能重复结算用量或造任务。未获供应商用量回执的请求保留待核对预算，不声称模型 API 恰好调用一次或供应商一定不重复计费。

规划输出允许 **0..N 项变更**。零项须记录“当前无新方向/等待何种变化”等简短依据并消费相应触发；自身完成事件不再触发自身。零项、队列暂空均不代表 Run 已完成，结束仍遵守 PROJECT §12.3。

版本按相关领域变化校验；心跳、日志输出不使研究快照失效。授权撤销、任务控制和预算变化仍在提交与执行前强校验。持续冲突须有有界退避和可见原因，不形成模型重算风暴。

### 2.3 转向与停止

规划可以请求停止或替换任务，但只能形成业务命令。`runs` 固化请求并停止新派发，Runner 确认旧进程与连接回收后才释放冲突资源或使替代任务可执行。已派发的命令/参数和既有证据不可改写。需要立即停止走 cancel；温和转向等当前有界调用收尾。unknown 未核对时不得换任务名重新执行。

模型规划暂不可用时，已提交、前提仍成立的任务可继续；需要新判断的分支明确等待。恢复、到期处理和取消不依赖模型在线。

## 3. 持久任务与多步研究

Research Frontier 是 ResearchTask、依赖和状态的查询结果，不再保存第二份具有执行权的 Markdown todolist、frontier 队列或自由文本黑板。界面待办与图均由这些记录派生。

每项任务至少记录：`run_id/task_id`、角色、服务/入口绑定、稳定研究问题标识、相关访问条件版本、来源任务与证据、预期产物、停止条件、优先级依据、状态/版本、租约。研究问题标识由程序登记；模型可提出新问题，但不能靠改写标题/随机标识规避已有同义任务。精确重复由程序拒绝，语义相似项交规划合并或说明差异，保留已尝试方法。

依赖是**类型化产物与前提**：生产任务、产物引用/版本、消费任务、要求的事实、验证方式、失效条件。`completed`、退出码 0 或模型勾选不能单独解锁后继。机械条件由程序判定；需要语义判断的前提引用带证据的决定，并标注不确定性。凭据只传受控引用，不进入共享文本或跨 Run 继承。

例如 A 识别服务，B 验证当前访问条件，C 研究一项依赖该访问条件的方法：A/B 执行结束但条件不成立时 C 保持阻断；产物可用才允许 C 领取；B 的访问条件失效后 C 重新判断。涉及执行许可的撤销同时触发停止；普通矛盾观察触发复核，不改写过去结果。独立的 D 分支可继续。

新增/修改依赖拒绝环，失败或取消传播明确的阻断原因。重启不重复已经完成的步骤，也不自动把上游失败转成下游成功。改计划不删除旧依赖与历史决定。领取时重新核对前提，不能只在入队时检查。

P2 首个切片固定版本化限额：待研究任务数、每轮新增数、规划最大并发、防抖最大等待、无进展阈值、模型输出上限和退避；在固定靶场校准后记录数值，再接入真实模型。无进展用新增有效证据、前提变化或假设被支持/反驳衡量，不能用改标题衡量；不增加单服务时长上限。

## 4. 服务事实、研究血缘与只读复用

使用 PostgreSQL 关系记录，按需投影两类业务图；LangGraph 只保存会话阶段和引用。投影的节点与关系语义、投影边界、展示状态与业务状态的区分、时间语义与查询约束见 [ADR-0015](../adr/0015-graph-semantics-and-projection-boundary.md)；本节只固定两类图各自保存什么。

- **服务事实关系**：Project 内规范化 IP 定位 Host，Host + transport + port 定位 Service，Web 入口同时保留连接目标、scheme、Host/SNI 与路径语义。程序计算键与归属，保守处理编码、大小写和查询参数，不能把不同入口过度合并。
- **研究血缘关系**：Run 内任务、假设、观察、Finding 与 Evidence 通过派生、产出、引用、支持或反驳等明确关系相连，锚定服务/入口。每条关系有来源和版本，不把所有自然语言自动变成图边。
- **观察**：不可覆盖原始记录，保存 Run、调用、来源、时间、访问条件、解析器/模型版本和置信信息。纠错新增更正或撤回关系。相同 IP/端口的不同运行观察不相互覆盖，矛盾可并存。

同 Run 的任务可按相关性读取持久事实视图，追加自己的观察或建议。首版不建设全平台共享资产真相或跨 Run 自动实时继承：用户明确关联历史 Run/Finding 后，只导入固定版本的只读证据引用和历史上下文。程序检查项目归属、可访问性、保留期和当前授权；外部目标线索不成为新授权。

历史引用记录源 Run、源对象版本、导入时间和使用目的。它可以启发本轮任务，不自动满足本轮认证、目标现状、漏洞实证或覆盖条件；当前结论需新的验证或明确标注仅审阅历史证据。过期/撤回/缺失显示状态，不能复制为本轮新证据。禁止改写来源；需要纠正时在本 Run 新增记录并引用来源。只读复用不消除内容污染，仍按不可信数据处理。

## 5. 上下文与模型运行边界

规划每次以业务快照构建上下文，Worker 可保留任务内会话，Reviewer 与报告步骤使用独立上下文。摘要只作索引：保留来源、覆盖范围、生成版本、反例和未决项；活动/unknown 调用、权限、停止条件和依赖不能因压缩消失。原文失效如实显示，不能由摘要恢复“事实”。

模型请求持久记录角色/用途、provider/model、输入快照 hash、提示词/Schema 版本、开始结束、结果/拒绝、用量、重试与费用是否已知；不记录内部思维链。规划、Worker、风险检查、Reviewer、报告开销分别展示且汇入 Run 总额；保留复审额度，报告不能占用未知用量的预留。输入输出预算和提供方数据设置都在发送前检查。

必须先移除 P0 的两个实现假设，再接远程模型：

1. 模型不能在持有 Run 行锁的 `runs.plan()` 事务中调用。harness 在事务外产生建议，runs 只负责准备/提交及校验；取消、续租不能等待模型。
2. 任务、会话和决策 ID 不能只由 `run_id + role + step` 决定；要绑定独立 task/session、状态版本及稳定尝试标识。两个 Worker 与多轮补证可并存且重放仍幂等。

模型暂不可用、拒绝、限流、Schema 错误、版本冲突与执行 unknown 各用明确原因与有界恢复；不通过切模型绕过服务限制。模型失败不能清空已提交任务、历史尝试或证据。

事务外模型调用仍需有界调度：模型、搜索和准备工作占满其并发额度时，取消、授权撤销、控制续租、结果接收与对账仍有可用处理能力，不排在这些慢工作之后。此处定义职责和验收，不要求另起服务或第二套调度框架。取消/到期后的晚到模型结果保留用量与来源，提交前检查原快照、任务和 Run 状态；不得派发已失效的建议。对账与结束判断按原业务版本进行，不能靠另问模型推断是否完成。

### 5.1 环境身份、准备与独立复现

按 [ADR-0014](../adr/0014-execution-lifecycle-and-environment-identity.md)，harness 请求研究所需的工具/环境能力，`runs` 校验预算与授权，Runner 在固定 profile 下准备、绑定实例并回传事实；模型不提供任意宿主挂载、网络或容器管理参数。P1 的实例身份、停止确认与当前健康检查在动态准备下继续成立。

在 P1 的 EnvironmentManifest 上补充固定来源/提交/hash、依赖锁与解析版本、构建配方及结果、工具版本和兼容环境键。一次准备请求关联自己的来源、日志、预算和产物；成功取得可用产物后才能绑定目标会话。安装成功只表示环境准备完成，不计目标覆盖或漏洞证据。失败修复受同一预算和有限重试约束；实际执行结果未知时仍先对账，不因改用新环境再次执行。

更新生成新的清单与制品。Run 已选择的版本保持固定；确需新增版本时显式记录选择与调用绑定，旧调用和旧证据继续引用原版本。清单是可重建环境的描述，目标会话私有工作区另行保存；无法固定的依赖或已缺失制品须记录复现限制，不以相同工具名称视作等价环境。

Reviewer 按证据所引用的来源/环境版本建立新实例、新工作区并重新校验当前权限和健康，不继承 Worker 的可写层或进程。清单相同只说明选择了相同环境输入，不证明工具输出可信；仍按第 7 节核对原始交互、反例与独立证据。原环境不能重建时标记环境原因，可以审阅已有证据，但不能标为现场复现，也不能据此裁定漏洞不存在。

## 6. 策略与风险判断

程序先判断范围、时限、权限、预算、profile 和可强制执行的限制；硬拒绝不能被 LLM 或一般人工“继续”覆盖。模型可以分析操作类别、预期副作用和会话退出条件，但不签发执行票据。目标数据操作遵循 [PROJECT §9.1](../../PROJECT.md) 和 [ADR-0012](../adr/0012-minimal-proof-and-target-data.md)。

### 6.1 默认最小实证与退出

默认 Run 策略包含 RCE 等较高影响漏洞的最小实证；策略在创建 Run 时展示并固化，执行不因漏洞名称/严重性另设人工许可。旧授权快照不得静默放宽，操作员明确收窄的范围/类别继续生效。Agent 应依据证据自主推进适用验证，有确定禁止副作用的方法拒绝后换方法，不能把“未单独批准 RCE”当阻断理由。

RCE 成功后只读采集最低必要的身份、主机/执行环境与时间信息，保存实际命令、受信采集时间、目标连接信息、证据 ID 和退出/回收确认；命令示例与身份/时钟歧义见总纲第 9.1.1 节。留证完成立即退出该验证分支，不进行业务数据读取、权限提升、驻留或横向研究。Reviewer 独立验证采用同样边界，不能以影响评分或补证为由制造损害。

### 6.2 目标数据与遗留

禁止破坏、删除或修改目标已有记录、文件、配置、权限与日志。只有确实不可避免且不覆盖已有数据、不造成真实业务损害的独立测试新增记录可以按默认策略执行；按最低必要数量、分批和预算上限推进。平台自己的工具/准备沙箱写入与资源回收继续按原有契约执行。

`runs` 管理测试新增数据记录，`execution` 提供调用与实际结果，`evidence` 保存原始引用，`timeline` 展示预期/实际影响：计划先登记必要性、位置、预计数量/体积与上限；结果登记可得的对象标识/测试标记、数量、时间和遗留状态。模型只能作明确标注的解释/估计，不能制造精确数量或“已清理”事实。结果未知时保留未知并防止重复创建。

新增数量上限与“大量”提示阈值按动作/数据类型在 P2-C 固定并校准，记录实际值与规则版本；任何数量都须登记，超过提示阈值立即展示，达到执行上限停止，不能用未到“大量”阈值省略报告。无法确定安全数量或业务影响时该方法阻断。普通授权内新增不逐条请求人工许可。

Run 摘要和报告必须附测试新增数据/遗留清单，大量脏数据醒目标明；失败、取消、零 Finding、低分过滤均不例外。不自动删除或修改新增测试记录，交操作员处理。报告输入版本包括这份清单，后到的执行结果或数量更正使旧报告标记待更新；只允许说明可核查的事实，不宣称无副作用。

### 6.3 辅助风险判断

HTTP 方法、删除类路径、参数和代码静态分析仅作辅助信号；`GET/POST` 也可能修改数据，路径分隔符规则只能减少部分误报。非 Web、加密流量和任意脚本不能被这类规则完整覆盖。要求严格操作语义时使用能强制限制的 `restricted-tools`；没有适用受限接口就说明能力不足，不降级为任意 Shell。

必要的风险检查超时、拒绝或无法判断时，返回 `risk_assessment_unavailable` / `risk_assessment_inconclusive` 并阻断受影响动作，可选择既有授权内更低风险的方法或请求具体补充条件；不自动放行，也不让整个 Run 的独立分支停住。预授权普通动作不重复要求人工审批。模型风险判断与人工 Approval 分开记录，内容变化使原判断失效。

## 7. 证据、复审与报告版本

### 7.1 采集与显式绑定

原始 Evidence 在执行时由受信执行层归档，先形成完整性元数据再提供引用；不能等到 Finding 绑定时才截取不断变化的流量。SHA-256 标识内容完整性，不证明来源可信、现场确实发生或不可篡改。相同内容可复用存储字节，但每次采集仍保留独立 call_id、目标、时间与来源记录，不能按 hash 合并不同执行事实。

Finding 与 Evidence 多对多关联。每条 EvidenceBinding 记录 Finding/主张版本、证据及具体片段、用途、简短理由、创建者/时间与版本：

| 用途 | 含义 |
| --- | --- |
| `baseline` | 正常对照 |
| `proof` | 支持当前漏洞主张的直接证明候选，标签本身不提升证据等级 |
| `verification` | 补充验证或独立复现；另外记录是否 fresh_replay |
| `supporting` | 适用条件、环境或辅助资料 |
| `counterevidence` | 反例或反驳主张的证据，不能因不利于结论而删除 |

显式绑定由 Worker、Reviewer 或人工提交结构化引用，程序校验归属、对象版本、可读性和片段范围；模型可提建议，不能凭域名、时间邻近或“浏览过”自动绑定。跨服务主张逐项列出服务和证据；跨 Run 证据走第 4 节历史引用，禁止绕过读权限或改写来源。

### 7.2 分段生成与并发控制

1. **审查输入**：提交候选 Finding 后，Reviewer 读取固定的主张、绑定、反例和证据状态，校验支持程度；缺证据形成有限补证请求，不编造绑定。无 Finding 也形成覆盖/未决摘要。
2. **生成报告**：审查输入稳定后，独立上下文的报告步骤依据同一快照组织文字；保存结构化输入与引用清单，输出不反向修改证据等级或人工裁定。允许先生成明确标为待复审的草稿，不能显示为最终确认。

`evidence_version` 是 Finding 的证据集合版本：新增、撤销、更正绑定、证据可用性改变均推进。主张变更推进 `finding_version`，机器/人工裁定分别有自己的版本。写入 Review/报告必须检查所依据的版本；生成期间发生变化返回 HTTP 409 / `version_conflict`，保留旧产物为历史，不替换当前有效报告。修改历史只读来源返回 HTTP 403 / `inherited_record_read_only`；无权读取的对象沿用统一访问策略，不通过错误泄漏存在性。

Run 汇总报告固定范围、覆盖、自动结束记录、测试新增数据/遗留，以及全部 Finding/Review/HumanDecision/评分与入库判定的输入清单和版本；不能只检查某一个 Finding 的 evidence_version。新反例、更正、人工决定或补证使旧报告标记待更新，但不覆盖已导出历史。人工作出的决定永不被报告模型改写。

报告任务按输入版本去重、合并事件、限制并发并单独计费；每个输出块不触发重生成。报告失败不阻碍执行资源回收，确定性 Markdown/JSON 仍可导出事实、证据索引与限制。人工决定变化只允许无目标执行的报告更新，不重新打开自动研究；任何再次调用模型仍需有效数据设置与可用预算，不能隐含无限后台费用。

### 7.3 保留与恢复

原始/脱敏副本分别固定 hash 与转换来源；模型只能读取允许发送的视图。按保存策略回收后保留索引和缺失原因，证明用途有效期届满并不删除材料；报告区分历史事实、当前适用性与可读性，不悄悄移除反例或显示仍可复现。共享 blob 回收核对全部活跃/固定引用，工具缓存回收不删证据；冻结保护、有效性与保留分离按 0006 §5/§9。

备份恢复同时验证业务库、图检查点、Runner 账本和证据/制品清单的兼容恢复点；恢复后先停止新增执行并对账。只有数据库恢复成功不等于 Run 可安全继续。事件/checkpoint/报告历史都有容量与保留政策，保护活跃恢复引用；规划使用持久触发记录，不能靠可能过期的 SSE 历史维持正确性。

### 7.4 严重性评分与漏洞库准入

采用 [漏洞评分与入库规格](./0004-finding-admission.md) 和 [ADR-0013](../adr/0013-severity-and-finding-admission.md)：CVSS v4.0 评分与证据状态、机器复审、人工裁定分别保存；正式漏洞库默认只收达到中危且具有实质影响、证据充分和人工确认的发现。低危/无害信息保留研究历史；版本命中、高分 CVE 和模型置信度均不能单独入库。

`runs` 管理评分版本与准入判定，harness 提供有证据的指标建议，程序校验并计算分数；漏洞库是通过门槛的 Finding 视图，不复制一份漏洞/证据真相。新增证据、更正评分、反例与政策版本变化均重新检查准入和报告版本。评分用于结果筛选，不赋予新的执行权限，也不能要求破坏性实证来获得高分。

## 8. 实施切片与验收

### 8.1 实施前 Phase 0

按 [0006 §10](./0006-state-model-and-delivery.md#10-phase-0映射与兼容策略) 先盘点实际来源并固定旧语义映射/兼容读，再定义 verified 对象映射、六轴字段与引用、冻结清单 schema、默认确认等级与有效要求版本。该 Phase 0 是 P2 的设计/迁移准备，不重新定义 P0 阶段，也不提前改代码或跳过 P1。旧状态不存在相应数据时不凭文档生成结论、复审或人工确认。

后续按依赖交付，不要求同一个 commit。0006 的字段/版本设计归 B/D、资源归 E、UI 归 F；无新部署服务或生产编排框架。

### 8.2 纵向切片

| 顺序 | 最小纵向成果 | 验收重点 |
| --- | --- | --- |
| P2-A | 固定证据驱动的多任务循环与事务外模型 Interface | 同初始事实、不同工具结果决定不同动作；两个 Worker 的 ID 独立；模型等待时取消/续租可进行；不把场景标签当证据 |
| P2-B | 事件规划与串行依赖闭环，含前提门、尝试/调用、完成判定及六轴关联版本 | A→B→C 产物解锁；独立 D 不受阻；漏通知、重启、重复/旧规划、零项、防抖饥饿、结束竞争；三值门和复合主张分别处理，未决受限结束正确 |
| P2-C | 真模型、联网研究与洁净动态准备 | 固定来源/版本、安装失败修复、普通用户执行、有限特权；资料提示注入不改权限；默认最小 RCE 留证即退出，禁止破坏/删改；必要新增数据有上限与实际记账 |
| P2-D | 显式证据绑定、六轴主张/复审/准入、判据与确认等级、版本化报告/冻结清单 | 按 0004/0005/0006 校验多对多/反例/历史只读、等级/复合/失效、报告冲突与保留分离；缺证据/机器复审/预算如实呈现，入库仍需人工；低分过滤不隐藏遗留 |
| P2-E | 单 Run 持续推进与运营验收，含容量、查询压力与两类长时验证 | 假时钟跨昼夜与有限长时靶场、故障恢复、预算停止、完成后无新目标动作；备份恢复、保留/存储满与敏感数据展示检查；容量与负载验收按第 9.4 节 |
| P2-F | 研究图与工作台基础可视化（独立切片，可用固定业务记录） | 按 0007 的四组摘要、服务/分支泳道、调用/证据详情和异常场景验证；显示状态不写业务事实，最新版本校验，未知/未决/隔离摘要与水位可见 |

上述是实施切片，不是已创建或已完成的 GitHub Issues。开工时按本规格建/关联任务并落实阈值，阶段状态只在 STATUS 更新。P1 不等待 P2 图界面或完整报告开发。

额外必须覆盖：规划期间新事实不丢；上游成功但前提不成立不解锁；依赖前提撤回；停止确认前不得启动冲突替代任务；相同 hash 不混淆采集归属；同 IP 不同 Run 不覆盖现状；新反例到达时旧报告不能覆盖；模型不可用仍可停止与导出。

ADR-0014 的验收分别归原有切片：P2-A 用阻塞的模型 Adapter 占满模型工作容量，验证取消/续租/对账仍推进，晚到结果不重开已停止任务；P2-C 验证准备失败不计目标覆盖、工具更新保留旧绑定；P2-D 验证 Reviewer 不继承私有工作区、缺失原环境不冒充复现；P2-E 验证同一逻辑会话重建后实例变化、旧调用历史与 unknown 仍需对账。以上是待实施的验收要求，不是已经运行的测试结果。

数据边界验收使用自建靶场：默认策略无需 RCE 类别审批，显式禁用与旧快照不会被自动放宽；同名命令的写入参数/组合被拒绝；成功最小留证后退出，受限身份不被误写为宿主 root；必须删改原数据的方法被拒绝；必要新增按量记录，大量新增、创建结果未知、取消/失败及无入库漏洞时仍完整披露，Agent 不执行删除清理。

评价在相同靶场、访问条件、模型/工具版本和总预算下，对比固定扫描与 Agent，再对比有无增量规划。多次重复报告有效证据率、误报/漏报、重复尝试、每个有效发现成本、规划零项比例、冲突/等待、完成时间与资源增长。规划收益不足先减触发和职责，不以增加 Agent 数量作为改进。P3/P4 再按证据增加适配器、长时优化或扩展部署。

## 9. 图语义与调度的成对验收

本节与 [ADR-0015](../adr/0015-graph-semantics-and-projection-boundary.md)、[ADR-0016](../adr/0016-scheduling-and-resource-policy.md) 配套，承担两者的验收要求；主张与能力类判据的验收见 [0005 规格](./0005-capability-claim-criteria.md) 第 8 节。每组同时给出“必须通过”与“必须拒绝或明确保留未决”两侧：**任一指标单独达标不算通过**，避免靠全部放行或全部阻断取得单项好看的结果。

### 9.1 成对验收组

| 规则 | 必须通过 | 必须拒绝或明确保留未决 |
| --- | --- | --- |
| 类型契约 | 新方法满足适用契约及确认等级后可 confirmed | 改名省略必要要求，或无适用判据送审后越过要求 |
| 契约配置 | 合法契约加载并通过展开校验；专用类型正确附加要求 | 专用契约省略通用或能力类必需维度；契约变更后沿用旧评估 |
| 分类未决 | 争议分类可继续研究并保留证据 | 未决被记成拒绝或通过；未决未进入受限结束记录 |
| 替代前提 | `any_of` 中一个有效成员成立即通过研究前提检查 | 仅有未知成员却判为成立 |
| 联合前提 | `all_of` 所有成员成立后通过 | 缺少任一必要成员仍然通过 |
| 硬约束 | 前提满足且独立控制检查通过后派发 | 把授权等硬约束放入研究前提组 |
| 尝试与查重 | 参数不同的对照、合法重复调用与瞬态重试正常处理 | 用粗指纹直接阻断，或绕过未知调用核对 |
| 跨服务统计 | 多视图引用同一尝试，覆盖按实际证据归属 | 改主锚点改变统计，或把引用服务算作已测试 |
| 展示状态 | 本地拖拽、筛选不产生研究状态变化 | 画布标签进入模型上下文或修改业务结论 |
| 恢复与部分结果 | 重建实例保留身份链，可读取已归档观察 | 新实例抹去旧调用，或部分结果冒充完整实验 |
| 投影滞后 | 显示水位，操作经最新业务版本校验 | 使用旧画布状态越过版本检查 |
| 时间与冻结交付 | 保留时间矛盾、历史判断及当前证据可用性 | 伪造全局顺序，或证据过期后仍声称可核验、可复现 |
| 查询压力 | 预算内查询正常返回，控制路径达到验收目标 | 查询无限扩张、静默截断或挤占控制能力 |

### 9.2 补充反例与正向用例

除第 9.1 节外，以下情形同样必须成立：

1. 变更主锚点后，历史覆盖比例、成本统计与结算记录不变。
2. `all_of` 中一个成员满足不能掩盖另一个未知成员；`any_of` 只有未知成员时不得判为成立。
3. 完全相同的命令作为对照请求必须照常执行，结论标记为“需比较”而不是“重复”。
4. 进行中或结果未知尝试的已归档证据可支持明确范围的有限主张，但不冒作已完成实验，不合并采集身份或绕过未知动作核对；四维限制随引用。
5. 清空本地存储并刷新后，恢复相同筛选范围时业务对象、状态与证据语义一致（不要求像素级一致）。
6. 同一尝试内重建实例：图上不新增节点，但可追到实际实例与调用。
7. 无确认持有者时显示“停止未确认”，不得显示已释放或被某个任务占用。
8. 投影落后于游标时显示水位，此刻操作按最新业务版本校验。
9. 目标返回时间与采集时间或发布序矛盾时，不重排、不隐藏矛盾、不用于排序。
10. 两个 Run 的事件不并入同一时间轴；比较视图并排显示且对齐键明确，按采集时间的近似对齐必须标注为启发式，且不创建证据绑定、不进入结论。
11. 冻结图修订交付后，证据过期仍能区分“当时所知”与“现已不可核验”，且不声称可复现。
12. 正向：参数不同的对照请求属同一尝试；合法瞬态重试不新增研究节点。
13. 正向：新发现的服务扩张研究前沿仍计为进展（判据是新增依据与去重，不是前沿规模）；分类未决期间独立合法研究继续推进。

### 9.3 指标口径

- **误阻断**：在已标注的固定验收集中，合法新方法被错误阻断的数量为 0，并报告样本数、误阻断率与重复抑制率；两项指标同时作为门槛。
- 合法对照、复现与瞬态重试不计作应抑制的重复；精确重复提交与语义相似研究分别统计；F1/F2 只发出比较提示，不计入“已抑制重复”。
- 重复抑制率的分母是夹具中明确标注的无效重复；分母为零时标为不适用。
- 夹具与标注是版本化制品（置于 `lab/`），报告须带夹具与标注版本；标注规则变化后不得沿用旧指标。

### 9.4 容量与两类长时验证

| 类别 | 用途 | 不能替代 |
| --- | --- | --- |
| 合成夹具与加速事件 | 逻辑、积压、突发更新、阈值与截断行为 | 真实长时运行 |
| 墙钟持续运行 | 内存与连接泄漏、磁盘与证据增长、租约时序、恢复 | 逻辑覆盖的广度 |

- 固定硬件/软件版本与负载矩阵：每 Run 1 / 10 / 50 / 100 IP，1 / 2 / 4 / 5 个活跃 Run，每 IP 1 / 5 服务，模型等待注入 0 / 50 / 90%，准备快/慢/失败，目标快/慢/超时，以及重启/在途取消/事件突发。全矩阵用合成/加速事件测逻辑；墙钟 24 小时覆盖代表性负载，至少记录 1 Run/10 IP 与 5 Run/100 IP 两格，不暗示全矩阵均已运行。
- 指标包括控制接受/暂停/取消/恢复 p50/p95/p99、续租及预算事务/结果入库延迟、符合调度资格集合的等待上界与分布、无进展原因、事件/投影滞后、图展开耗时、前端/三服务内存及连接增长、磁盘/证据增长、槽占用/空转和未知动作误重试（必须为 0）。受阻或失去授权目标不纳入无饿死承诺。
- 每格通过须同时满足事先固定并版本化的响应/等待/增长阈值、无错误资源释放、无越过全局及单 IP 物理额度、unknown 未盲目重试。阈值须在运行前锁定，不能事后移动标准；参数校准与通过记录分开。
- 图查询压力采用对照测量：比较有无图查询压力时的取消响应、控制租约续租、预算事务与结果入库延迟，差值须在验收指标内。
- 邻域与路径查询额度、渲染路径切换阈值与调度份额留实测校准并版本化；校准结果写入验证记录，本节不预设数值。

### 9.5 切片归属

字段与版本契约归 P2-B/D；基础可视化（P2-F）可与其他切片并行，不等待完整研究闭环；P2-E 承接容量、查询压力与两类长时验证。P1 顺序不变，不因本节或图界面开发调整。

本节是验收要求，不是已经运行的测试结果，不创建实施任务，也不改变当前阶段状态。

### 9.6 状态、冻结与 UI 的配套验收

状态成对用例唯一清单见 [0006 §11](./0006-state-model-and-delivery.md#11-成对验收与切片)，UI 场景与可访问性见 [0007 §7](./0007-research-workbench-ui.md#7-验收与场景)。重点覆盖：程序/独立/人工等级与准入分离、server 实证不前置人审、lapsed 读时失效且不自动重开研究、any_of 替代证据仍可成立、全局容量未知时背压但管理可用、兼容读取不推造确认、冻结/保存/当前核验分离。域行为经 runs 的公开 Interface、Runner 测试 Adapter 和真实 PostgreSQL 验证；界面经固定业务记录与关键用户流程验证，不以图坐标或内部类断言业务正确。
